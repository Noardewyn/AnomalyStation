## 0. Headline findings

1. **tg REPLACES BYOND's native Move.** `/atom/movable/Move` is defined TWICE on the same type (atoms_movable.dm:687 and :763). The 1st def never calls `..()`; it is a full reimplementation (Exit -> Enter -> PRE_MOVE -> `loc =` -> Exited -> Entered -> Moved). The 2nd def (pull/diagonal/glide/z-fall wrapper) calls `. = ..()` into the 1st. So the native engine Move, Crossed, Uncross, Uncrossed, native Enter/Exit logic is NEVER executed. `Crossed/Uncross/Uncrossed` are `CRASH` stubs (:942,:966,:976); `/atom/Exit` deliberately omits `..()` (_atom.dm:630) so Uncross is never called.
2. The ONLY engine mutation primitive the chain needs is **`loc = X`**: it maintains `contents` and x/y/z and fires NOTHING (no Enter/Exit/Entered/Exited/Crossed/Moved). tg manually calls Exited/Entered/Moved afterwards (evidence: doMove:1190-1225; openspace.dm:46-47 "Enter() only called by Move(), not forceMove()").
3. **`RESOLVE_ACTIVE_MOVEMENT`/`SET_ACTIVE_MOVEMENT`** (`__DEFINES/movement_info.dm`) make `Moved()` fire exactly once per movement and BEFORE any nested movement started by a handler (qdel inside Entered, forceMove inside Exited...). This re-entrancy design must be preserved bit-exact (section 4).
4. `get_turf(A)` is `#define get_turf(A) (get_step(A, 0))` (`__DEFINES/turfs.dm:79`), 3836 call sites; `get_area(A)` = `isarea(A)?A:get_step(A,0)?.loc` (:86). So `get_step/get_dir/get_dist` MUST resolve an atom inside nested containers to its outermost turf.
5. Most of atoms_movable.dm (languages, factions, vv, emissive, lighting, deadchat) is irrelevant to M0; the movement-relevant core is ~lines 1-60 vars, 149-273 Initialize/Destroy (Destroy calls `moveToNullspace` at :261, after `..()` and the contents qdel), 392-471 zMove, 525-681 pulling+abstract_move, 687-1029 Move/Moved/Bump/Entered/Exited, 1032-1089 hearing/area sensitivity (called by mob/Initialize), 1139-1333 doMove & spacemove, 1467-1473 buckled.

## 2. Engine contract the C# shim must provide (exact semantics)

### E1. `loc` assignment (movables)
- `loc = X`: if X == loc no-op. Else remove src from old loc `contents` (others keep order), append src at END of X.`contents` (order = arrival order; `/turf/Enter` iterates it, ties in first_bump keep earlier). X==null => nullspace (x=y=z=0, not in any contents).
- **Silently refused** if X is src or X is (transitively) inside src (cyclic): doMove detects it via `if(loc == oldloc)` after the assignment (:1193-1197). Shim must reproduce (leave loc unchanged, no error).
- Fires NOTHING. No Enter/Exit/Entered/Exited/Cross/Crossed/Uncross/Uncrossed/Moved/signals. Settled: BYOND ref, Entered proc: "Directly setting the object's loc or step_x/y vars does not result in a call to Entered() or any other movement side-effects."
- `x/y/z` of a turf-located movable = turf coords; of a movable-in-movable = 0 (use get_turf). `locs` (multi-tile read-only list) = tiles covered by bounds; BYOND ref, locs var: "If loc is not a turf, it will be the only item in the locs list. If loc is null, locs will be empty."
- `contents += X` on an area/atom is equivalent to `X.loc = container` (turf.dm:261 `new_area.contents += src` reparents turf to area). `turf.loc` is its /area.
- `new T(loc)`: atom placed in `loc.contents` BEFORE New/Initialize runs (particle_holder.dm:28 reads `loc`); evidence tg treats it as NOT firing Entered/Cross (effects_sparks.dm:87-95 comment; aquarium_kit.dm:43 creates in null then forceMove "to trigger handle_entered"; tg substitutes `COMSIG_ATOM_AFTER_SUCCESSFUL_INITIALIZED_ON`, atoms_initializing_EXPENSIVE.dm:50). Settled: BYOND ref, Entered proc: "The same goes for creation or deletion of an object at a location."; New proc (atom): "By the time New() is called, the object has already been created at the specified location". Firm shim rule (`Dm.@new` places the atom silently before `New`) with a test that no Entered/ENTERED signal fires.
- Direct `loc =` outside atoms_movable.dm on real movables: oranges_ear.unassign, particle_holder.dm:28, shared_particle_holder.dm:22, decal.dm:97 (`loc = null` deliberately skipping doMove), door.dm:205 (filler), golfcart.dm:488; the rest are `/image` (images' loc is not contents). Expose as `Atom.SetLocRaw()`.

### E2. `step(ref, dir)` = `t = get_step(ref, dir); if (!t || t == ref.loc) return 0; return ref.Move(t, dir)`
Dispatches to the OUTERMOST Move override; returns Move's return. Diagonal dirs allowed (Move splits them). Called inside Move itself for diagonals (:787 etc.) so it re-enters the override chain. 82 uses; `step_to/step_away/step_towards/step_rand` 49 uses (+`get_step_to/away/towards/rand` 73, mostly movement_types.dm and AI); `walk*` only in SDQL admin wrappers (M0: omit all). Settled: when `get_step` is null (map edge) or equals `ref.loc` (dir 0), Move is NOT called and step returns 0. OpenDream `DMCompiler/DMStandard/_Standard.dm:168-174`: "var/NewLoc = get_step(Ref, Dir) / if (!NewLoc || NewLoc == Ref.loc) return 0 / return Ref.Move(NewLoc, Dir)"; its BYOND-parity test `Content.IntegrationTests/DMProject/Tests/move.dm` (world.maxx = 2) expects an empty trace, i.e. no Move call, for `step(protag, 0)` and for `step(protag, EAST)` at the edge. This matters because tg's outer Move runs `check_pulling(z_allowed = TRUE)` BEFORE its `!newloc` bail (:766-769), so calling Move(null) would have observable side effects. Test: a logging Move override on the mover, assert Move is not called when stepping off the map edge or with dir 0 (a plain adjacent pull cannot tell the two policies apart: check_pulling does nothing then).

### E3. Coordinate helpers (all operate through the loc chain to the outermost turf)
`get_step(ref,dir)` (577 uses; dir 0 = get_turf), `get_dir(a,b)` (395; used on movables inside containers, e.g. doMove:1186, Enter:440), `get_dist` (493), `locate(x,y,z)`, `block()`, `get_area()`. ### E4. Native base procs that tg overrides but that the shim must still provide as `..()` roots
- `Bump(obstacle)`: native no-op returning null (movable Bump does `. = ..()` at :985). BYOND ref, Bump proc, default action: "If the obstacle is a mob and src is in its group, swap their positions." tg never puts mobs in the builtin `group` list (grep finds only tg's own regex/fluid vars named `group`), so the no-op shim is equivalent; document it at the shim. `Bumped` is tg-defined (_atom.dm:407), native never calls it.
- `Enter(mover)` default for non-turf atoms: TRUE. Settled: BYOND ref, Enter proc: "Areas, objs, and mobs will always permit anything to enter by default." Turf Enter is tg's (turf.dm:434, "Do not call ..()"). `openspace/Enter(movable, oldloc)` takes a 2nd arg that tg's Move never passes (null).
- `Exit`: tg-defined for all atoms (_atom.dm:629, signal only; closet override :1079 opens the closet and has a side-effect of relocating the mover).
- `Crossed/Uncross/Uncrossed`: must exist only as `CRASH`; shim must never invoke them. `Cross` is tg-defined (:934), called ONLY by `/turf/Enter`.
- `client/Move(loc,dir)` native base (mob_movement.dm:121 `. = ..()`) = `mob.Move(loc,dir)`; not M0 (no clients).

### E5. Iteration/containers
`for(var/x in list)` and `contents` iteration iterate a **snapshot copy**. BYOND ref, for list proc: "When you loop through a list, with the exception of looping through world, you're actually looping through a copy of that list." (tg relies on it, see signals.dm:123 comment "does not implicitly copy the list"). The one exception, `for(... in world)`, is a live enumeration (atom.md section 9). Needed because Enter/Cross, Destroy (`for(movable_content in contents) qdel(...)` :258) and Initialize (`for(content in src) initialize_occupant` turf.dm:171) mutate contents mid-loop. List ops used in chain: `-` and `|` and `&` set ops preserving order (`old_locs - new_locs`, `locs - new_locs`, `. |= src`); `-` removes each item's LAST occurrence (datum-signals-components.md, DM list).

### E6. Time/tick
`world.time` (ds, `float` per D64), `world.tick_lag`, `NEXT_VISUAL_TICK = GLOB.last_maptick_time + tick_lag` (visual_helpers.dm:30; last_maptick_time set by world/Tick, world.dm:274, which `TgWorld.Boot` runs as the first world phase of every tick). tg's chain itself never sleeps, but some override in the tg tree may, so at the snapshot `docs/ai/specs/generated/colored-slots.tsv` (authoritative; `docs/ai/specs/colored-procs.md`) colours these slots that the chain of section 3 calls, all with `suspends = yes`: `Move`, `Moved`, `forceMove`, `doMove`, `abstract_move`, `moveToNullspace`, `Enter`, `Exit`, `Entered`, `Exited`, `CanPass`, `CanAllowThrough`, `Cross`, `Bump`, `setDir` and the helpers `check_pulling`, `stop_pulling`, `move_from_pull`, `handle_buckled_mob_movement`, `newtonian_move`, `Process_Spacemove`, `on_changed_z_level`, `zFall`, `transfer_occupant` and `set_pull_offsets`. These slots return `DmTask`/`DmTask<object>` and every call into them is awaited or uses a call form of `docs/ai/specs/waiting-model.md` section 5; a chain that does not sleep completes synchronously. `Bumped` and `/datum/thrownthing` `finalize` (3c) are coloured only through `waitfor = FALSE` definitions (`suspends = no`, waiting-model.md 4.2 and 5.4: callers never wait for them). `Crossed`, `Uncross`, `Uncrossed`, `CanPassThrough`, `set_glide_size`, `set_currently_z_moving`, `has_buckled_mobs` and `has_gravity` are not coloured.

### 3f. Diagonal Move (def2:779-829)

## 9. Hazards for faithful C# translation
1. Same-path duplicate proc defs (Move x2): chain per source order (later wraps earlier; `..()` in later => earlier; `..()` in earliest => native base). Settled by OpenDream `DreamObjectDefinition.SetProcDefinition`: "if (HasProc(procName) && !replace) { ... proc.SuperProc = GetProc(procName);" (a later definition on the same type gets the earlier one as its parent). Emit `Move` (last def, virtual) + non-virtual `Move__d0`.
2. `..()` with no args forwards the CALLER's full positional args, including params the override does not declare: `carbon/Move(NewLoc, direct)` and `human/Move(NewLoc, direct)` (carbon_movement.dm:9, human_movement.dm:27) drop `glide_size_override, update_dir` from their own signature, yet moveloops pass `update_dir` and it must reach def1. Rule: every override of a proc is emitted with the base's full parameter list (positional, names are local aliases); arglist/`args` kept.
3. Override param names/positions differ (NewLoc/direct/dir/step_x...). Positional mapping only. No named-arg calls to Move/forceMove exist (grep).
4. DM `null` vs `0`/FALSE: `.` defaults to null; Move returns null when `newloc==loc` and when both first-step attempts of a diagonal move fail (3f); any tri-state Move return type must cover both. The setters use OPPOSITE conventions: `set_pulling` (:580) and `set_pulledby` (:610) return FALSE for "no change" and the old value (possibly null) for a change (comment at :582/:612 "null signals there was a change"); `set_anchored` (:1140) and `setGrabState` (:1739) return a bare null for "no change" and the old value for a change. Need a DmValue-ish type for those; bool is fine for Enter/Exit/Cross/CanPass.
5. DM truthiness of ints/objects: `thing.layer > x || thing.flags_1 & ON_BORDER_1`; `return mover.movement_type & PHASING` (returns int). Emit `!= 0` in boolean contexts, keep int return where callers store it.
6. Re-entrancy everywhere: handlers can qdel/forceMove the mover mid-chain; every `QDELETED(mover)` check in turf.Enter must be kept; `oldloc` is re-read after Exit/Enter/PRE_MOVE (:734).
7. `SEND_SIGNAL` macro evaluates target 2-3x and NULL target runtime-errors; helper `Signals.Send(target, sig, args)` must keep "no listeners => NONE" and must not allow handlers to be cancelled by another handler unregistering (snapshot).
8. `set waitfor=FALSE` is declared on the ROOT proc (`atom/Bumped`, `area/Entered`, `throw_impact`) and IS INHERITED by overrides: `door/Bumped` (door.dm:254) and `door/window/Bumped` sleep via `open()` without redeclaring it and window/Bumped never calls `..()`. Settled by OpenDream `DMCompiler/DM/DMCodeTree.Procs.cs:36-41`: "if (procDef.IsOverride) { ... if (parent.Attributes.HasFlag(ProcAttributes.DisableWaitfor)) proc.Attributes |= ProcAttributes.DisableWaitfor;" (tg has no `set waitfor = TRUE` that could undo it). 125 `set waitfor` lines in 99 files. Translation (wave-0 waiting decision): waitfor=FALSE is a property of the callee slot, inherited by every override, implemented by a callee-side wrapper, so the Move chain calls `Bumped`/`area.Entered` like normal procs and gets their `.` at the callee's first suspension; it never blocks on them.
9. `SIGNAL_HANDLER` (=`SHOULD_NOT_SLEEP`) handlers must be synchronous; the waiting-model analyzer enforces that no `await` appears in handlers (ANOM0005, waiting-model.md 5.6, D97). A handler that calls a proc in a `DmTask` slot (`suspends = yes` in `slots.tsv`) writes `Waiting.NoSleep(Foo(...))` (completed: value; still pending: reported as "slept inside a no-sleep context" and detached), and INVOKE_ASYNC becomes `Waiting.Detach(Foo(...))` (docs/ai/specs/waiting-model.md).
