## DM builtins and idioms the shim must provide

### ..() (parent proc call) (operator, ~23353 uses)
- DM: Calls the next implementation up the type chain with the arguments this proc received; overrides may freely change param lists and arity (Destroy(force=FALSE, ...) callback.dm:79, component New(list/raw_args) _component.dm:43, Initialize(...) in ~400 components). 449 procs are marked SHOULD_CALL_PARENT.
- C#: base.Proc(p1, p2, ...) emitted explicitly by the translator, which expands '..()' with the current parameter list mapped by position to the base signature; keep one canonical C# signature per proc name per hierarchy and adapt arity in the dynamic trampoline

### PROC_REF / TYPE_PROC_REF / GLOBAL_PROC_REF (macro, ~9715 uses)
- DM: PROC_REF(x) and TYPE_PROC_REF(T,x) expand to the string 'x' (compile-time checked via nameof); GLOBAL_PROC_REF(x) is the path value /proc/x. Call-by-name resolves against the receiver's RUNTIME type at call time (virtual dispatch). Values flow through lists/vars (connect_loc.dm:32 connections[signal]).
- C#: readonly struct ProcRef(string Name); PROC_REF -> new ProcRef(nameof(Method)); TYPE_PROC_REF(/datum/element,x) -> nameof(Element.x); GLOBAL_PROC_REF -> GlobalProc.Of(nameof(Fn)); resolution via DmProcTable.Resolve(runtimeType, name) cached as Func<object, object?[], object?> that pads missing args with null and drops extras

### RegisterSignal / RegisterSignals / UnregisterSignal (datum proc, ~7363 uses)
- DM: Listener-side registration (signals.dm:16-104): silently returns if src or target is QDELETED; _signal_procs[target][sig]=proc is written BEFORE the override check; lookup[sig] is null | single datum | list in registration order; Unregister collapses a 2-list to a single datum.
- C#: Datum.RegisterSignal(Datum target, object signal, ProcRef proc, bool @override=false); RegisterSignals(Datum target, DmList signals, ProcRef proc, bool @override=false); UnregisterSignal(Datum target, object sigOrList). Keep _listen_lookup/_signal_procs as DmList assoc (turf code copies them, turf.dm:119, change_turf.dm:108-112)

### SIGNAL_HANDLER (macro/lint, ~4679 uses)
- DM: Expands to SHOULD_NOT_SLEEP(TRUE) (dcs/helpers.dm:11), a SpacemanDMM lint only. 4679 uses and 0 SIGNAL_HANDLER_DOES_SLEEP escapes, so every handler is guaranteed non-suspending.
- C#: [SignalHandler] attribute + Roslyn analyzer forbidding await/sleep inside; lets SendSignal be plain synchronous C#. A handler that calls a proc in a `DmTask` slot (`suspends = yes` in `slots.tsv`) writes `Waiting.NoSleep(Foo(...))`, and INVOKE_ASYNC inside a handler is `Waiting.Detach(Foo(...))` (waiting-model.md)

### SEND_SIGNAL / SEND_GLOBAL_SIGNAL (macro, ~1588 uses)
- DM: ( !target._listen_lookup?[sig] ? NONE : target._SendSignal(sig, list(target, args...)) ) (dcs/helpers.dm:5): arguments are evaluated ONLY when a listener exists; returns OR-ed bitfield of handler returns; source datum is injected as first arg. SEND_GLOBAL_SIGNAL sends on SSdcs.
- C#: static int Dm.SendSignal(Datum target, string sig, params object?[] a) with fast path 'if (target._listen_lookup is null || !target._listen_lookup.Has(sig)) return NONE'; add 0..4-arg generic overloads to avoid array allocation; for args containing calls (47 single-line sites) emit 'target.HasListener(sig) ? ... : NONE' to keep laziness

## Hazards

- List iteration is snapshot-based in DM (for-in copies the list) and tg RELIES on it: Destroy iterates _datum_components while component Destroy calls _RemoveFromParent which edits that very list (datum.dm:150-158, _component.dm:127-147); _clear_signal_refs iterates _signal_procs while UnregisterSignal deletes from it (datum.dm:186-187). DmList enumeration must snapshot (or throw-free live indexing) or every qdel throws 'collection modified'; ranged 'for(i in 1 to length(L))' reads the live list element by element, but its bound `length(L)` is evaluated once at loop start (signals.dm:124; OpenDream CreateRangeEnumerator pops start/end/step once). Rule: foreach over DmList always uses Snapshot().
- Typed for-in loop silently filters by type, 'as anything' does not: _component.dm:487 'for(var/datum/component/component in ...)' skips non-components while :153 'as anything in' does not. 3358 'as anything' typed loops tree-wide; translator must emit OfType-style filtering for typed non-anything loops and unchecked casts for 'as anything', and DM var type annotations are NOT enforced casts (C# InvalidCastException risk) - use unchecked/as casts.
- Truthiness and length rules: empty list is truthy, empty text/0/null falsy; length(datum)==0 is how _SendSignal and GetComponent tell 'single object' from 'list' (signals.dm:115, _component.dm:263); '||=' assigns on falsy (signals.dm:32-34). Provide Dm.Truthy/Dm.Length and forbid raw C# 'is null' where tg tests truthiness; HAS_TRAIT relies on '_status_traits[trait] ? TRUE : FALSE' (an empty sources list would be truthy).
- DM break/continue inside switch refer to the ENCLOSING LOOP (signals.dm:82-100 uses 'continue' and 'break' inside switch inside for; 'break' at :91/:98 leaves the for loop). Settled: BYOND ref, break statement: "If no label is specified, the innermost loop containing the break statement is assumed." (a DM switch is not a loop, and "Fall-through behavior isn't possible in the default DM syntax"). C# switch captures `break` (C# `continue` inside a switch already targets the loop). Translator must lower DM switch to if/else chains or use labelled goto/flags; signals.dm:82-100 is the test case.
- SEND_SIGNAL evaluates its argument list only when a listener exists (dcs/helpers.dm:5). C# eager argument evaluation changes behavior for args with side effects or cost (47 single-line SEND_SIGNAL sites contain nested calls). Hot path: Move chain sends 5+ signals; avoid params-array allocation when no listener (generic 0..4 arg overloads + HasListener pre-check).
- Runtime-error semantics differ: in DM an unhandled CRASH/runtime error aborts only the current proc and returns its `.` to the caller (often null) - proven by stack_trace.dm:1-4 which exists precisely to log without ending the caller. 911 stack_trace + 939 CRASH sites. Port (wave-0 decision, a recorded deviation in `docs/ai/DEVIATIONS.md`, allowed by D86 because runtimes are bugs; never call it DM semantics): stack_trace = log + continue; CRASH/NRE = exception that unwinds to the nearest isolation boundary, where `World.ReportRuntime` logs it. Boundaries: each scheduler entry, `Waiting.Detach`, subsystem fire/ignite, each timer callback, each signal handler call inside _SendSignal (so one broken handler does not skip the remaining listeners), each callback Invoke, per-item process()/Life() in processing subsystems, InitAtom during atom initialization (try is free when nothing throws). tg code that inspects `.` after a runtime gets an explicit try/catch where it is translated.
- Proc override signatures are not uniform in DM: component New(list/raw_args) vs datum New(...), Destroy(force) vs Destroy(force=FALSE, ...) (callback.dm:79), Initialize(...) overridden with a different arity in ~400 components and invoked only through arglist; Attach/Detach same. C# virtual overrides need identical signatures, so translator must emit a canonical dynamic bridge per proc name (object?[]/DmArgs -> typed call with null padding, extras dropped, named-arg binding by parameter name) and use it for every call()/callback/signal/arglist path; direct typed calls stay typed.
- Named-argument smuggling through assoc lists: AddElement(/datum/element/x, a = 1) becomes list(type, 'a'=1); DM cannot distinguish a named arg with null value from a positional text (dcs.dm:55). DmList must preserve assoc values through Copy(start), '+', args slicing, and the translator should resolve named->positional statically when the target type literal is known (common case) and fall back to runtime binding by parameter name.
- usr is implicit, mutable and survives sleeps: callbacks capture WEAKREF(usr) at creation and re-impose it when invoked from timers (callback.dm:68-102). In a headless M0 world usr is null almost always, but the continuation type of the waiting model must carry usr (and src) so do_after/timers resumed later restore it; Callback.Invoke's DF_VAR_EDITED admin branch (callback.dm:113-116, GLOB.AdminProcCallHandler, WrapAdminProcCall) is admin-only: translate as NotTranslated.
- gc_destroyed is null | -2 | world.time and QDELING is a truthiness test: a datum queued at world.time == 0 (toy world start, unit tests) has gc_destroyed 0 and reads as alive (garbage.dm:274-275). Start the toy world clock above 0 or type QDELING as '!= null' (documented deviation).
- GC model has no .NET analogue: SSgarbage.HandleQueue uses refcount() and del() (garbage.dm:148-264,281-316), QDEL_HINT_HARDDEL*/FINDREFERENCE are meaningless. Keep qdel()'s observable behavior (guards, PREQDELETED cancel, -2 marker, QDELETING signal, hint switch: LETMELIVE restores gc_destroyed=null unless force; IWILLGC sets world.time) and shim Queue/HardDelete; real memory is .NET GC. Tests that assert 'GC'd' should use a WeakReference probe, not refcount.
- Weakref identity: resolve() must verify weak_reference == this (ref-reuse guard) and not QDELETED; hard_resolve skips the QDELETED check (2 users). REF() strings/locate() are only needed for logs and for bespoke-element hashing; use WeakReference<Datum> inside Weakref and a lazy id registry for REF (ids must be stable per object and never reused).
- tg quirks that a faithful translation will copy: _component.dm:112 inserts the typepath I (not src) into components_of_type on exact-match priority insertion (only reachable with several components of one type, e.g. DUPE_ALLOWED + subtypes); weakrefs.dm:61-68 Destroy qdels the TARGET datum then returns LETMELIVE; callback.dm:63 CALLBACK(null, proc) silently becomes a GLOBAL_PROC call; signals.dm:37-44 an unsuppressed override replaces the proc but returns before touching lookup; _component.dm:284-288 GetExactComponent returns null when dc[type] is a list. Mark each with '// tg quirk' and add a test; decide per D86 whether to fix (cheap ones) or copy.
- Signal ordering contract (the M0 acceptance scenario): handler order = registration order (lookup[sig] append, signals.dm:46-53); two-element list collapses to a single datum on removal (:83-84) preserving order; dispatch snapshots registrants and proc names before calling anyone (:119-128) so handlers registered during dispatch are NOT called and handlers unregistered during dispatch STILL are; single-registrant path skips the snapshot (:116-117); return value is OR of all handler returns with null coerced to 0 (NONE | call(...), :117). Reproduce exactly and unit-test it.
- GLOBAL_* initialization order is semantic: InitGlobalX procs run in DM definition (compile) order from tgstation.dme, init expressions may use earlier globals (GLOB.x or even bare name because the proc is a method of GLOB), and GLOB init must precede make_datum_reference_lists (globals.dm:69). SS* subsystems are GLOBAL_REAL (created by the MC, not by GLOB) so SSdcs must be constructed before the first AddElement or SEND_GLOBAL_SIGNAL.
- Bitfield arithmetic: signal returns are OR-ed as DM floats (24-bit safe), null|x == x; C# should use int with Dm.Bits(object?) coercion; COMSIG_* includes non-string members (bitfield result flags like COMSIG_COMPONENT_PERMIT_PASSAGE (1<<0) and COMSIG_LIVING_ADJUST_STANDARD_DAMAGE_TYPES, a list(...) used with RegisterSignals) so the defines converter must emit typed constants (string / int / DmList), not only strings (47 object-like non-string COMSIG_* names, see Files).
- Parametrized signal and trait macros interpolate DM text ('cooldown_[cd_index]', '"[effect_id]-trait"', COMSIG_CD_STOP) where the argument may be a typepath or datum: converter emits static string functions using Dm.Str(object?) to match DM formatting (numbers, paths).
