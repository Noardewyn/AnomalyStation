## 1. How do_after works (datums/timed_actions.dm, 256 lines)

`do_after(user, delay, target, timed_action_flags, show_progress, extra_checks, interaction_key, max_interact_count, cog_icon, cog_iconstate, bar_override)` (:211) is a global proc that BLOCKS its caller and returns TRUE/FALSE.

1. Guards: `!user` -> FALSE (:212); three `ASSERT`s with messages (:215-217: delay must be num, target must not be num, delay must not be atom); `delay <= 0` -> TRUE immediately, no signals (:219).
2. Interaction cap (mobs only): default `interaction_key = target`, or for a list target the sorted (`sortTim`+`cmp_text_asc`) `ref()` strings joined by "-" (:222-231). `current >= max_interact_count` -> bare `return` = **null, not FALSE** (:236); else `do_afters[key]++` (:238). `mob.do_afters` is a lazy assoc list (`modules/mob/mob_defines.dm:175`).
3. `SEND_SIGNAL(user, COMSIG_DO_AFTER_BEGAN)` (:240), `new /datum/timed_action(...)`, `. = action.await()` (:242-243), then decrement/remove the key (:245-251), `SEND_SIGNAL(user, COMSIG_DO_AFTER_ENDED)` (:252). There is no try/finally: a runtime in `new`/`await` leaks the `do_afters` count (faithful translation must not add one).
4. `New` (:24-55): stores user/flags/extra_checks; normalises `targets` to a list (:29-34; a caller-supplied list is used by reference, `on_target_deleted` then mutates the caller's list, :141); builds `progressbar` only if the user mob (or `bar_override`) has a client (:37-38), `cogbar` if `cog_icon` non-null and delay >= 10 ds (:40-41; the default icon is non-null, so every client-less do_after >= 1 s still makes a cogbar); non-mobs get IGNORE_* flags (:47-48); mobs multiply `delay` by `mob.cached_multiplicative_actions_slowdown` unless IGNORE_SLOWDOWNS (:49-50); `start_time = world.time; end_time = start + delay` (:52-53); `register_signals()` (:55).
5. `register_signals` (:71-93): always `COMSIG_QDELETING` on user; `COMSIG_MOVABLE_MOVED` unless IGNORE_USER_LOC_CHANGE; `SIGNAL_ADDTRAIT(TRAIT_INCAPACITATED)` (a runtime-built string, `"addtrait incapacitated"`) unless IGNORE_INCAPACITATED; `COMSIG_LIVING_CHANGENEXT_MOVE` only with DO_AFTER_CHECK_NEXT_MOVE; unless IGNORE_HELD_ITEM: `COMSIG_MOB_EQUIPPED_ITEM`, `COMSIG_MOB_SWAP_HANDS`, `COMSIG_MOB_UNEQUIPPED_ITEM`; per target != user: `COMSIG_QDELETING` and (unless IGNORE_TARGET_LOC_CHANGE) `COMSIG_MOVABLE_MOVED`. All handlers are `SIGNAL_HANDLER` (never sleep) and all end in `cancel()`.
6. Handlers (:134-191): `on_user_moved(source, old_loc, dir, forced, old_locs)` returns if `user.loc == old_loc`; else cancels if `isnull(user.drift_handler)` (in M0 always null), else cancels when any target is not `Adjacent(user)`. `on_target_moved` mirrors it with `source.drift_handler`/`source.Adjacent(user)`. `on_item_equipped` cancels only if the item is the active held item; `on_item_dropped` only if `source.active_hand_index == hand_index`. `on_changenext_move` cancels if `next_move > world.time`. The Moved signal is sent at `game/atoms_movable.dm:902` with `(old_loc, movement_dir, forced, old_locs, momentum_change)`.
7. `await()` (:103-120): `START_PROCESSING(SStimed_actions, src)`; `status = WORKING`; `while(status == WORKING && world.time < end_time) sleep(world.tick_lag)`; if still WORKING it calls `process()` once itself (:110-111: "await will tick first before the subsystem itself"); result = `status == SUCCEEDED`; ends/removes bar and cog; `qdel(src)`. The `delay` param of `await` is unused.
8. `process(seconds_per_tick)` (:122-132): `extra_checks.InvokeAsync()` falsy -> `cancel()`; updates the progressbar; `world.time >= end_time` -> `status = SUCCEEDED; return PROCESS_KILL`. `cancel()` (:95-101): no-op unless WORKING; sets FAILED and `STOP_PROCESSING`. `Destroy` (:57-69) forces status FAILED, qdels bar/cog only if still WORKING, `STOP_PROCESSING`.
9. `SStimed_actions` (`controllers/subsystem/processing/timed_actions.dm`, 6 lines): `PROCESSING_SUBSYSTEM_DEF`, `SS_TICKER|SS_NO_INIT`, `RUNLEVEL_GAME|RUNLEVEL_POSTGAME`, `wait = 1` (tick), priority 360 (`__DEFINES/subsystems.dm:166`). The parent `fire` (`processing/processing.dm:19-30`) copies `processing`, walks it from the END, calls `thing.process(wait * 0.1)`, stops on `PROCESS_KILL` (=26), and checks `MC_TICK_CHECK` after each item.

### Timeline of a 1 s (10 ds) do_after at tick T (port tick order of the wave-0 decision: `RunDue` with the MC coroutine inside, then the command phases)
T (player-command phase, after the MC already fired this tick): constructor, signals registered, `START_PROCESSING` (no `process()` in T, SStimed_actions already ran), loop body entered, `sleep(world.tick_lag)` queued for T+1 BEHIND the MC's own sleep, caller suspended. T+1..T+19 (tick = 0.5 ds): the MC wakes first and SStimed_actions runs `process()` -> `extra_checks` poll + bar update; then the await wakes, sees WORKING and `world.time < end_time`, sleeps again (FIFO keeps this order every tick). T+20: the MC's `process()` makes the 20th poll, sees `world.time >= end_time`, sets SUCCEEDED and returns PROCESS_KILL (STOP_PROCESSING); the await then wakes, leaves the loop, does NOT call `process()` itself (status is no longer WORKING), returns TRUE and qdels the action. tg's comment at timed_actions.dm:110 ("await will tick first before the subsystem itself") assumes the opposite order, in which the await makes the 20th poll itself; the observable result is the same either way (20 polls, TRUE at T+20). tg's `.github/guides/TICK_ORDER.md` (sleepers resume in the order they slept, step 2; client verbs run after SendMaps, step 6) supports MC-first for a verb-started do_after; pin the port's order with a test. A move at tick K fires the Moved handler synchronously inside the Move chain -> `cancel()` (FAILED, STOP_PROCESSING); the awaiting proc notices only when it next wakes (tick K+1), so cancel latency is 1 tick and the caller gets FALSE. Command phases must run after the drain (they do in the port); a `START_PROCESSING` before the MC fired in tick T would add a poll in T itself.

## 2. Translation hazards in timed_actions.dm (cite when translating)

- **Shadowed parameter vs field (:27 vs :44-50).** `New` assigns `src.timed_action_flags = timed_action_flags` FIRST, then `&=`/`|=` the LOCAL parameter (UNIT_TESTS strip :44, non-mob IGNORE_* :48). `register_signals()` reads the field, so the non-mob IGNORE_* flags never reach it (harmless: those signals never fire on non-mobs) and the local copy only steers the slowdown branch. C# must keep the parameter `timed_action_flags` and the field `this.timed_action_flags` distinct (verbatim names, translation-rules.md section 2) and keep the statement order.
- **Delay captured before slowdown.** The progressbar gets the unslowed `delay` (:38) and `delay *= slowdown` happens later (:50); the bar clamps at its goal (`progressbar.dm:133`).
- **`null` slowdown.** `cached_multiplicative_actions_slowdown` is null until `mob/Initialize` runs `initialize_actionspeed()` (`mob.dm:98`, adds `/datum/actionspeed_modifier/base` with slowdown 1, `_actionspeed_modifier.dm:168`); DM arithmetic treats null as 0 (BYOND ref, * operator: "num or null (0)"), so `delay *= null` = 0 and the do_after succeeds instantly. The toy mob must set it to 1 (or port `update_actionspeed`), and the C# field must be `float` defaulting to 0, not 1, to stay faithful.
- **`extra_checks.InvokeAsync()` (:123)**: a callback that sleeps yields its current `.` (null -> falsy -> cancel). Extra checks must be synchronous procs; the shim `Callback.InvokeAsync` returns the sync result or null on first suspension. Typical checks are `CALLBACK(src, PROC_REF(x), args)` (89 call sites, `game/objects/items.dm:1245` wraps a nested callback `tool_check`).
- `astype(user, /mob)?.client` (:37) is a DM 516 builtin (123 uses) = C# `user as Mob`.
- `world.time` is float32: compare `world.time >= end_time` with the kernel's `Tick * TickLag` float; delays after slowdown can be non-multiples of 0.5, the loop exits at the first tick with time >= end.
- `Destroy` frees the bar/cog only while WORKING, otherwise lets them animate out via `QDEL_IN` timers (progressbar.dm:147, cogbar.dm:90): presentation only.
- `do_after` returns null in the cap case but `if(!do_after(...))` is the dominant use, so `DmTask<bool>` with false is safe; 9 sites `return do_after(...)` pass it up.

## 5. stoplag / CHECK_TICK / UNTIL translation rules

`stoplag.dm:7-26`:
- Branch A (:8-10): `if(!Master || Master.init_stage_completed < INITSTAGE_MAX) { sleep(world.tick_lag); return 1 }`. In a toy world with no `Master` this branch ignores `initial_delay` (1 tick sleep). Faithful port keeps it behind `World.MasterInitialized` (default TRUE for the toy world so stoplag(5 SECONDS) really waits; record as a flag, not a silent change).
- Branch B (:19-25): `i = DS2TICKS(initial_delay)`; `do { . += ceil(i * DELTA_CALC); sleep(i * tick_lag * DELTA_CALC); i *= 2 } while (TICK_USAGE > min(70, Master.current_ticklimit))` with `DELTA_CALC = max((max(TICK_USAGE, world.cpu)/100) * max(Master.sleep_delta-1,1), 1)`.
- Branch C (:15-17, `#ifdef UNIT_TESTS`): `sleep(initial_delay); return ceil(DS2TICKS(initial_delay))`.
- **Rule:** D31 forbids wall-clock inputs, so `TICK_USAGE`/`world.cpu`/`map_cpu` are the constant 0. Then DELTA_CALC = 1, the do-while runs once, and branch B collapses to branch C. Translate `stoplag` as: A (flag) then `await sleep(initial_delay ?? world.tick_lag)`, return `ceil(DS2TICKS(d))`. `initial_delay == 0/null` means `world.tick_lag` (:11-12). Note `stoplag(0)` and `stoplag()` are both one tick; `stoplag(1)` is 1 ds = 2 ticks.
- `CHECK_TICK` (`__DEFINES/_tick.dm:21`) = `TICK_USAGE > Master.current_ticklimit ? stoplag() : 0`: with usage 0 it is constant 0. Elide it (`// tg: CHECK_TICK elided`) and do NOT color its procs: ~84 files stay synchronous. Same for `CHECK_TICK_HIGH_PRIORITY`, `TICK_CHECK`, `VERB_SHOULD_YIELD`, `RUNNING_BEFORE_MASTER`. NOT for `MC_TICK_CHECK`: it is translated literally (`(TICK_USAGE > Master.current_ticklimit || state != SS_RUNNING) ? pause() : 0`), see section 4. Provide `Dm.TickUsage => 0` so the 96 `TICK_USAGE` mentions (22 files, mostly profiling) compile; revisit with a work-budget model in M1 if a server tick overruns.
- Wake order: BYOND resumes sleepers FIFO; the kernel orders by (tick, insertion), same (and the MC is one of those sleepers, see the section 1 timeline).

## 7. DM semantic traps the shim must pin down (write a conformance table; there is no BYOND here to diff against)

- **`round()`**: tg treats single-arg `round(x)` as FLOOR (`__DEFINES/maths.dm:44` comment; `FLOOR(x,y) = round(x/y)*y`, `CEILING`/`ROUND_UP` = `-round(-x)`), while the two-arg form is nearest-multiple (`siunit_isolated` comment: 999.9 rounds to 1000, `maths.dm:148-149`). Settled for `round(x)`: BYOND ref, round proc: "The first format returns the floor of A" (`round(-1.45)` outputs -2). Still open: `round(x, y)` at exact halves (the ref is silent; OpenDream uses banker's `Math.Round(a / b) * b`, DreamProcNativeRoot.cs:2151, so it is no evidence either way); pin it once a BYOND oracle exists. `DisplayTimeText` (`FLOOR(time*0.1, 0.1)`) is the float32 canary: C# must compute `x/0.1f` in float32 exactly like DM.
- **Numbers are float32** (D64 core numbers are `float`; D83 DM semantics via the shim); exact integers only to 2^24 (`SHORT_REAL_LIMIT`, `maths.dm:13`); bit ops are valid to 24 bits (`MAX_BITFIELD_SIZE`, `__DEFINES/_flags.dm:308`); `bit_count` assumes 16-bit fields (`maths.dm:203`).
- **`%` vs `%%`**: `%` truncates to integer operands (C-like sign), `%%` is the float modulus used by `MODULUS` (`maths.dm:57`, used by `DisplayTimeText`, `time_to_twelve_hour`, `SIMPLIFY_DEGREES`) and has the sign of the DIVIDEND (BYOND ref, %% operator: "It is equivalent to B * fract(A / B)."; fract keeps the sign of its argument), so `-180 %% 360` is -180. Provide `Dm.mod` and `Dm.fmod` (defines.md section 10).
- **null in arithmetic is 0** (see the slowdown trap; BYOND ref, + - * / operators: "num or null (0)"); `null` in text is `""`; `isnull` vs falsy (`0`, `""`, null are all false in `if`); `x ||= list()` (LAZYADD) assigns on falsy.
- **Text**: `length` is bytes, `length_char` is codepoints; `copytext`/`findtext` are 1-based, byte oriented (`_char` variants for unicode); `findtext` is case-insensitive, `findtextEx` exact; `sorttext(a,b)` is case-insensitive and its sign is the REVERSE of `cmp` convention (`cmp_text_asc(a,b) = sorttext(b,a)`, `cmp.dm:7-8`). `replacetext` accepts regex + proc replacer (`full_capitalize` passes `/proc/capitalize`). `regex()` objects have `Find`/`Replace`/`group`/`match` state (11 core uses): a thin wrapper over .NET Regex with DM option mapping.
- **Lists**: 1-based; assoc via `L[key]`; `list += x` appends but `list += list(..)` concatenates, hence `LIST_VALUE_WRAP_LISTS`/`UNTYPED_LIST_ADD` (`_lists.dm:14-18`); `L -= x` removes the LAST match, searching from the end (BYOND ref, Remove proc (list): "Removal starts at the end of the list (highest index) so that this operation is an exact reversal of Add()."; OpenDream `DreamList.RemoveValue` uses `LastIndexOf`); `L1 | L2`, `&`, `^` set ops; `Cut(a,b)` end-exclusive and negative-index aware; `Insert`, `Copy(a,b)` likewise. `.len = n` pads with null. Many helpers (`shuffle`, `pop`, `popleft`, `move_element`) rely on `Swap`/`Cut`/`Insert` semantics, so `DmList` must implement exactly those 10 methods before any helper is ported.
- **`ref()`/`REF()`** (1613 uses): must be a stable unique string per object (D-replication id), used as a sort/dedupe key; `TYPEID(thing)` slices chars 4-5 of it (`_helpers.dm:47`): only needed for `isfilter`, skip.
- **`LAZYACCESS(L, I)`** treats a numeric `I` as a 1-based index with bounds checks and a non-numeric `I` as an assoc key (`_lists.dm:68`); atom keys are by reference.
- **Time-unit macros are textual** (`SECONDS` = `*10`, `__DEFINES/time.dm:69`): rewrite `N SECONDS` as `N * SECONDS` at the same precedence (no added parentheses, defines.md 6.1); `MINUTES` = `SECONDS*60`. `TICKS` = `*world.tick_lag`.
- **`usr`/`world.push_usr`**: `datum/callback.Invoke` re-establishes `usr` from a stored weakref (`callback.dm:96-102`, `:134-139`); `usr` appears 183 times in core. M0 callbacks drop the weakref but keep an explicit `usr` argument convention (decide in translation-rules).
- `STOP_PROCESSING` is a brace-less 3-statement macro (`MC.dm:32`), `LAZYADD`/`LAZYSET` expand to `L ||= list(); L += I;`: translate to method calls, never inline into an unbraced `if`.
- `sleep` and `world.time` units are DECIseconds; `world.tick_lag` = 0.5, `world.fps` = 20 (`game/world.dm:496-519`).
