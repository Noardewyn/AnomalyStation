## 5. Converter design (generator "dm2cs-defines")

5.1 Pipeline (one-shot tool, regenerated from the tg clone; output committed):
1. Mini preprocessor over files in `.dme` order: object/function-like `#define` with `\` continuations, variadics (`name...` and `##name` comma-eating), `#undef`, `#if/#ifdef/#ifndef/#elif/#else/#endif` against a `-D` set (DM_VERSION=516, DM_BUILD=1659, CBT; everything else undefined; SPACEMAN_DMM undefined but see 6.5), `#error/#warn` -> diagnostics, comment stripping that is STRING-AWARE (`byond://` in bodies, vv.dm:42, admin.dm:48-79 breaks naive `//` stripping; I hit this in the prototype).
2. Keep doc comments: `///` / `/** */` above a define -> XML doc; trailing `//` -> doc; for signals parse `: (atom/old_loc, dir, ...)` (1,061 of 1,380 string signals have it) into a `SignalInfo` registry (name, string, arg names/types, return-flag names).
3. Classify body (not name): kinds in table 2; function-like per table 3. Anything unclassified goes to `defines.todo.json`, never silently dropped (D-style rule: no silent cuts).
4. Emit: one `partial static class Defines` per source file, file-for-file (`Defines/_flags.g.cs` ...) in namespace with `using static`, names kept VERBATIM (`COMSIG_MOVABLE_MOVED`, `HAS_TRAIT`, `get_turf`) so DM<->C# grep/diff stays 1:1 for the reference-first port. Return-flag defines indented under a signal become `ReturnFlags` members documented on the signal (350 in dcs).
5. Emit `defines.manifest.json` (name, kind, args, file:line, folded value, emit status). This is the SINGLE source the statement-level translator consults to decide, for every identifier in code, "constant / macro-expand / bare word" (rule 6.3).
6. Self-check: python folds every constant with float32 semantics -> golden values; a C# reflection test compares `Defines.X` to the golden value (catches int-division, precedence, `~` mask bugs below).

5.2 Typing rules for emitted constants: int literal/flags/`|`/`&`/`<<` of ints -> `int`; any fractional/exponent literal, any `/`, `**`, or float ref -> `float` with `f` literals (DM num = IEEE binary32); string concat -> `string`; typed by folding, not by regex. Force float division: `(1 / 64)` LIGHTING_ROUND_VALUE lighting.dm:35, `(50 / 100000)` DNA.dm:140, `(111 / 100000)` DNA.dm:142, `(1/6)` supermatter.dm:32, `1/3` inside `EM_MASK_MATRIX` lighting.dm:124 are all 0 in C# int math. Hard-fail on shift >= 24, on value > 2^24 that is not an explicit allow-list (SHORT_REAL_LIMIT).
Bitwise: DM bit ops are 24-bit. `ALL (~0)` _flags.dm:1 and `HEAL_ALL ~(HEAL_ADMIN|HEAL_RESTRAINTS)` mobs.dm:1035 are ~0 = 0xFFFFFF (16777215) in DM, -1 in C#. Emit `const int ALL = 0xFFFFFF;` and translate every `~x` as `(~x) & 0xFFFFFF` via `Dm.bitnot`. Settled: BYOND ref, ~ operator: "A must be between 0 and 2**24 - 1, giving an effective width of 24 bits."; OpenDream BitNot pushes `(~value) & 0xFFFFFF` (DMOpcodeHandlers.cs:1016). Keep an M0 conformance test. ALL is aliased by 8 more defines (`MUTE_ALL`, `FULL_BODY`, `CLEAN_ALL` ...) and `GLOBAL_VAR_INIT(ghost_role_flags, ALL)` admin.dm:157.

5.3 What the generator must NOT do: map by `COMSIG_` prefix (47 `COMSIG_*` defines are numeric return flags, e.g. `COMSIG_ATOM_NO_UPDATE_NAME UPDATE_NAME`); dedupe signal strings (6 distinct names share one string value: `COMSIG_PROJECTILE_PREHIT`/`SELF_PREHIT`="com_proj_prehit" signals_object.dm:453/459, `COMSIG_ITEM_UNEMBEDDED`/`FAILED_EMBED`, `COMSIG_ATOM_PRE_EMP_ACT`/`EMP_ACT`="atom_emp_act", `COMSIG_BEING_STRIPPED`/`TRY_STRIP`, `COMSIG_DEMORALISING_EVENT`/`TRAITOR_GRAFFITI_SLIPPED`, `COMSIG_PROJECTILE_POST_HIT_LIVING`/`SELF_`) - dispatch is by string value, so keep strings, never turn them into distinct enum ids; replace `__FILE__/__LINE__/__PROC__/__TYPE__` with the original DM path/line literals (not C# CallerFilePath) so TIMER_DEBUG/stack_trace output matches tg.

## 6. Translation rule set derived from the defines

6.1 Postfix unit macros (SECONDS 9,362 uses; MINUTES 978; HOURS 23; KILO 64; NEWTONS 17; MEGA 17; 132 define bodies use them). DM expands `X SECONDS` textually to `X *10`. Emit unit constants as VALUES (`const int SECONDS = 10; MINUTES = SECONDS*60; HOURS; DAYS; YEARS = DAYS*365; const float MILLISECONDS = 0.01f; DECISECONDS = 1; KILO = 1e3f ...; NEWTONS = 1; WATTS = WATT; JOULES = JOULE; EVENT_SECONDS = 0.5f; TICKS => world.tick_lag`) and rewrite syntactically `<operand> UNIT` -> `<operand> * UNIT` at the SAME precedence. That is textually identical to DM, including its pitfall `a / 5 SECONDS` == `(a/5)*10`. Most divisions by a unit are parenthesised (36 sites, e.g. wiremod.dm:72, surgery.dm:177, __HELPERS/maths.dm:196, time.dm:108), but two real sites divide by an unparenthesised unit and rely on the textual expansion: `modules/mob/living/carbon/human/_species.dm:1339` (`H.seconds_in_low_pressure / 80 SECONDS` = `(x / 80) * 10`) and `controllers/subsystem/ipintel.dm:71` (`REALTIMEOFDAY / 1 MINUTES` = `x / 1 * 10 * 60`). The textual-precedence rule is therefore mandatory: never parenthesise `N UNIT` "semantically". `seconds_per_tick SECONDS` (concrete_walls.dm:91, smoke 96/371) works with the same rule.
6.2 Call-site macro expansion: translator needs a real expander (named-arg aware, `#`/`##`, variadic) for statement/context-capturing macros; hygiene: macro-local `var/_L`, `_S`, `__move_args` get unique renames (C# forbids shadowing, CS0136); `do { } while(FALSE)` -> block; arguments that are not simple (identifier/member chain/call/literal) are bound to a temp when the macro evaluates the param more than once; for args with side effects DM's double evaluation is a bug nobody relies on (single evaluation is the intended semantics) - emit a lint when an arg containing a call is passed to a multi-eval macro.
6.3 Identifier resolution (affects every `list(...)` and call): inside `list()/alist()` and named call args, `key = value` with a bare identifier key is a STRING key unless the identifier is a defined macro (then the macro value is the key), e.g. `list(limit = 4, usage = list())` (id_cards.dm:14) vs `list(ZTRAIT_STATION = TRUE)` (maps.dm:134). Translator must consult the manifest. Macro names are also expanded after `.` (`nearby.is_blind()` -> `.has_status_effect(/datum/status_effect/grouped/blindness)` status_effects.dm:80; the `(...)` args are discarded); same for `become_blind/cure_blind/is_nearsighted` etc (member-call alias macros).
6.4 Interpolation in macro text: `"distortion_in_use_#[z_layer]"` traits/declarations.dm:15, `"[effect_id]-trait"` traits/macros.dm:12, `"cooldown_[cd_index]"` cooldowns.dm:74 -> `$"..{Dm.Str(x)}.."`; DM text conversion of numbers is %g-like with 6 significant digits (`"[1000000]"` -> `1e+06`) and typepaths print as `/obj/item`; implement `Dm.Str` once. ~30 parametrised signal/trait name factories (`COMSIG_ATOM_TOOL_ACT(tooltype)`, `COMSIG_WEATHER_*`, `COMSIG_CD_STOP`, `SIGNAL_ADDTRAIT`) become `static string` methods; they are why signals must stay strings.
6.5 Annotation macros: `SIGNAL_HANDLER` is `SHOULD_NOT_SLEEP(TRUE)` (dcs/helpers.dm:11; 4,665 uses) which expands to NOTHING in a normal build but is the contract "this proc never yields". Do not expand: map to `[SignalHandler]` (+ Roslyn rule: no `await`/yield inside; sync `void`), `SHOULD_CALL_PARENT` (446 uses) -> `[ShouldCallParent]` (analyzer: base call required), `SHOULD_NOT_OVERRIDE` -> a marker attribute (the proc stays `public virtual`, translation-rules.md section 4), `RETURN_TYPE` -> ignore (static types), `PRIVATE_PROC/PROTECTED_PROC` -> marker attributes `[DmPrivate]`/`[DmProtected]` with the proc's normal accessibility, `VAR_FINAL/PRIVATE/PROTECTED` (decl modifiers) -> a public field plus a marker attribute (translation-rules.md section 3), `UNLINT(x)` -> x. Real C# modifiers would break tg's own code: `VAR_FINAL/incapacitated` (mob_defines.dm:87) is assigned at runtime (mob.dm:468, so not `readonly`), `VAR_PRIVATE/atom_integrity` (atom_defense.dm:8) is written by `turf/Initialize` (turf.dm:188, so not `private`), and `PROTECTED_PROC(TRUE)` `Destroy` (datum.dm:126) is called from the global `qdel` (garbage.dm:377 `UNLINT(to_delete.Destroy(force))`, so not `protected`). Run the generator with SPACEMAN_DMM semantic ON for these names only.
6.6 List-valued defines are factories: a define `list(...)` expands to a NEW list at every use. `WILDCARD_LIMIT_*` (id_cards.dm:14-44) are mutated per ID card (`usage = list()`), `COMMON_ACCESS`/`REGION_ACCESS_*` (access.dm:296-557) are `in`-tested, `ALPHABET/VOWELS` (text.dm:114), `COLOR_MATRIX_*`. Emit `static DmList X => ...` (property, not field); a cache may be used only for provably read-only users.
6.7 `::` and typepath consts need type metadata (initial values): `COLOR_JOB_ASSISTANT /obj/item/clothing/under/color/grey::greyscale_colors` preferences.dm:186, `GAS_META` atmos_core.dm:181, `parent_type::desc` in MAGAZINE_TYPE_* magazines.dm:9 -> property reading the type's initial/default (the same facility as `initial()`: 3,230 uses in code).
6.8 Typecache globals live in the dir (is_helpers.dm `GLOBAL_LIST_INIT(turfs_without_ground, typecacheof(list(/turf/open/space, ...)))`): order of `GLOBAL_*` init follows include order (`gvars_datum_init_order`, __globals.dm:8). C# static field init order across classes is undefined -> generate an explicit ordered `GlobalVars.InitAll()` in `.dme` order.
6.9 Arg-less builtin-constant dependencies the shim must supply (referenced by define bodies but not defined in tg): TRUE, FALSE, NORTH=1 SOUTH=2 EAST=4 WEST=8, NORTHEAST/NORTHWEST/SOUTHEAST/SOUTHWEST, UP, DOWN, TOPDOWN_LAYER (=10000 per layers.dm:168), KEEP_TOGETHER, KEEP_APART, RESET_COLOR/RESET_TRANSFORM/RESET_ALPHA, NO_CLIENT_COLOR, PIXEL_SCALE, SEE_MOBS, SEE_OBJS, COLORSPACE_HSL/HSV, MS_WINDOWS. Numeric values must come from the BYOND reference/OpenDream, not guessed (REVERSE_DIR directional.dm:29 confirms UP/DOWN occupy bits 16/32).

## 8. Waiting model hooks present in the defines
Macros containing yield points: UNTIL (_helpers.dm:31, `while(!(X)) stoplag()`), SLEEP_NOT_DEL (_helpers.dm:35), SLEEP_CHECK_DEATH (mobs.dm:627), CHECK_TICK/CHECK_TICK_HIGH_PRIORITY (_tick.dm:21,31), ASYNC/INVOKE_ASYNC (callbacks.dm:8-21; `spawn(-1)` = run immediately until first block), QDEL_IN/QDEL_IN_STOPPABLE (timer, no sleep). MC_TICK_CHECK is NOT a yield: `pause()` (controllers/subsystem.dm:275) just sets `state = SS_PAUSED/SS_PAUSING` and returns 1, the caller does `if(MC_TICK_CHECK) return` and fire() is re-entered with `resumed=TRUE` - port as plain return, no coroutine. It is also NOT constant: besides TICK_USAGE it tests `src.state != SS_RUNNING`, which is true after the fire() slept (controllers.md 3.8), so translate it literally rather than eliding it like CHECK_TICK. `SHOULD_NOT_SLEEP(TRUE)` handlers (SIGNAL_HANDLER) must be provably sync. Macro bodies containing `return` mean the macro MUST be expanded inside the caller coroutine (cannot be a library method).

## 10. DM numeric/semantic traps the generated constants and macros rely on
- Division: DM `/` is always float; C# int `/` truncates. All translated `/` must be float (4 pure-numeric constant defines + `EM_MASK_MATRIX` above; 143 define bodies use `/`).
- `%` vs `%%`: 7 define bodies use `%` (ISEVEN, ISODD, ISMULTIPLE, WRAP_UP, IS_LEFT/RIGHT_INDEX, LASER_SHOTS); `MODULUS(x,y) ((x) %% (y))` maths.dm:57 is the "real" modulo and the only `%%` in code (about 22 call sites through MODULUS and SIMPLIFY_DEGREES). Provide `Dm.mod` (`%`: truncates both operands to integers first, C-like sign) and `Dm.fmod` (`%%`). Settled: BYOND ref, %% operator: "It is equivalent to B * fract(A / B)." and fract proc: "Returns the fractional part of the number A, with the same sign" (`fract(-1.45)` is -0.45), so the result has the sign of the DIVIDEND (a truncated remainder, like C `fmod`); OpenDream computes `fraction = a / b; fraction -= MathF.Truncate(fraction); return fraction * b` in float32 (DMOpcodeHandlers.cs:3131-3137, `ModulusModulusValues`). Implement `Dm.fmod(a, b)` as `b * (a/b - trunc(a/b))` in float32 and pin it: `-180 %% 360 == -180`, `-1 %% 3 == -1`, `540 %% 360 == 180`. tg quirk: the comment beside SIMPLIFY_DEGREES (maths.dm:136 "-180 becomes 180") is stale from the old floor-based MODULUS; keep the code, do not "fix" it. (SpacemanDMM's constant folder uses floored modulo; that is a linter, not the engine; re-check once if a BYOND install becomes available.)
- `**` power (12 define bodies): `Math.Pow`; right-assoc.
- `round(x)`/`round(x,y)`/`floor`/`ceil`: single-arg `round(x)` is floor, settled by the BYOND ref, round proc: "The first format returns the floor of A" (`round(-1.45)` outputs -2). CEILING/FLOOR/ROUND_UP/ROUND_PROB macros maths.dm:32-45 depend on it. `round(x,y)` rounds to the nearest multiple of y; its behaviour at exact halves (including negative halves) is NOT settled: the BYOND ref is silent and OpenDream uses `Math.Round(a / b) * b` (banker's rounding, DreamProcNativeRoot.cs:2151), so it cannot back a "not banker's" claim. Open item: pin it with a test once a BYOND oracle exists. `log(10,x)`, `sin/cos/tan/arccos` use DEGREES (`TODEGREES`, `ATAN2` maths.dm:68).
- Float32: DM numbers are binary32; `PI 3.1416`, `NUM_E 2.71828183`, `INFINITY 1e31` (NOT float.Infinity; maths.dm:11), `TODEGREES 57.2957795` must keep their literal values. `world.time` is deciseconds as float (D64): integers are exact to 2^24 (SHORT_REAL_LIMIT), multiples of 0.5 to 2^23 ds (about 9.7 days).
- Number->text: `"[x]"` 6 significant digits (see 6.4). Numeric keys 1 and 1.0 are the same list key in DM; int const vs float value in a C# `Dictionary<object,...>` would NOT match, so DmList must normalise numeric keys.
- `1 == TRUE`; `null` in arithmetic is 0 (BYOND ref, + - * / operators: "num or null (0)"). `+` on text: only text + text concatenates (BYOND ref, + operator); `"str" + num` is a runtime type-mismatch error (OpenDream Add throws `ThrowInvalidAddOperation`; the BYOND ref's try/catch example calls `a += "Hello"` on a number "a type mismatch error"), while `"str" + null` is `"str"` and `null + x` is x (OpenDream Add). Macros like span_* (`"<span ...>" + str + "</span>"`) therefore expect text or null; numbers must be interpolated (`"[x]"`).
