# 10. tgstation content and assets: what will have to be ported

Date: 2026-10-05. Baseline: local shallow clone `../tgstation` (a single commit `1d99bd7f` dated 2026-10-04; the repository has not changed). All numbers were obtained with commands or scripts; the scripts are in `docs/ai/research/10-scripts/` (Python 3, stdlib only; DMI and DMM are parsed by hand, without PIL). External facts are backed by pages that I actually opened.

An important caveat on method: types and their `icon_state` values were counted by static parsing of DM code (`10-scripts/dm_types.py`). This is a lower bound: some `icon_state` values are computed at runtime (`update_icon_state`, `update_overlays`). Check: the number of `/obj/item/...` declarations in column zero found by grep is 11,389, and my parser gives 11,426 (a 0.3% discrepancy). Types generated by macros (for example `/directional/north` for wall-mounted objects) are not seen by the parser: of the 10,822 types found in the maps, 8,765 are in its dictionary.

## Summary

- tg graphics are **48,691 `icon_state` values in 1,448 DMI files** (47 MB compressed, 138,892 frames, about 264 million pixels). 91.6% of states are 32x32; 75.9% of states have **one** direction, only 23.6% have 4 directions, 0.5% have 8. For 3D this means: views from an arbitrary camera angle cannot honestly be derived from sprites.
- Actually unique visual types (static minimum): items 6,363, structures 1,541, machines 710, mobs 345, turfs 395, effects 1,014. In total about **10 thousand "model slots"** for full parity, about **4.5 thousand** if grouped by type families (4th path level).
- MetaStation: 2,702 unique atom types in the map (2,296 excluding areas, space, helpers and landmarks), of which 1,453 are unique (icon, icon_state) pairs. A heavy-tailed distribution: **87 families give 80% of instances, 274 give 90%, 591 give 95%**; 46.7% of types occur on the map exactly once.
- A human's appearance is assembled from 23 main overlay layers (plus fractional sublayers), 575 sprite accessories, 30 species (7 enabled for a round) and 3,979 wearable types. Discrete body combinations alone number about 4.6e11, equipment combinations about 8e27. Pre-rendering is impossible; runtime composition is required.
- tgui: **352 windows** (React/TS, 141 thousand lines), but the exchange with the game is a JSON state plus `act()`, and the dependency on BYOND comes down to about 20 `Byond.*` calls. Replacing the windows with native Godot UI is expensive; a WebView shell with a shim is cheaper in labor, but ⚠️ Godot core has no WebView: a third-party plugin is needed, and it is limited (see the "Verification" section, item 8), so "cheap" holds only for desktop.
- Sound: 116.5 MB, 3,793 ogg files, a format already friendly to Godot. 5 pixel TTF fonts. Texts are few (0.6 MB).
- Licenses: code is AGPLv3, assets are declared CC BY-SA 3.0 "unless otherwise stated"; details are in `08-legal-licensing.md`. The asset strategy depends on whether the project is willing to be copyleft. ⚠️ "Otherwise" does occur in practice: `sound/` contains files under CC BY-NC (28 mentions in 11 attribution files), meaning not all of the sound can be used in a commercial project (see F8 and "Verification").

## Findings

### F1. Sprites (DMI)
Format: PNG plus metadata in a `zTXt` chunk with the key `Description` (text `version/width/height/state/dirs/frames/delay`). The chunk was found in all 1,457 files, with 0 parse errors.

| Metric | Value | How obtained |
|---|---|---|
| DMI files | 1,457 (1,448 in `icons/`, 9 in `tools/`) | `find . -name '*.dmi' \| wc -l` |
| `icon_state` | 48,691 (icons/) | `10-scripts/dmi_parse.py`, `dmi_stats.py` |
| Frames x directions | 138,892 | same |
| Size | 47.1 MB compressed; about 264 million pixels (1.06 GB RGBA if everything is loaded) | same |
| Directions | 1-dir 36,974; 4-dir 11,470; 8-dir 247 | same |
| Animated states | 5,687 (11.7%), with 63,752 frames (46% of all frames), maximum 213 frames | same |
| Cell size | 32x32: 1,229 files in `icons/` (1,236 together with `tools/`), 91.6% of states; 64 px or more on at least one side: 139 files, 1,427 states; 96 px or more: 51 files | same (wording and 1,229 corrected during verification) |

The large ones: 480x480 are screen overlays (parallax, FOV, menus), 504x532 is Nar-Sie, 512x512 is the station explosion. Megafauna mobs are 64-96 px.

Volume by folder (files / states): `obj` 680 / 25,090; `mob` 403 / 12,041; `turf` 138 / 6,424; `effects` 124 / 1,767; `hud` 43 / 1,695. The "heaviest" files: pipes (666 states), `areas_station.dmi` (409), `belt_mirror.dmi` (356).

Smoothing: 465 types use `SMOOTH_BITMASK`; walls are DMI files with 47 states (about 40 materials); 200 `*.png.toml` files in `icons/` are sources for the autogenerator (`icons/Cutter.md`, `cutter_templates/`). The DMI files there are generated output.
Confidence: high.

### F3. Mob appearance
Sources: `code/__DEFINES/mobs.dm`, `human_update_icons.dm`, `bodyparts/`, `sprite_accessories/`.
- Layers: `TOTAL_LAYERS 23` main layers plus 22 fractional sublayers (for example `OUTER_HAIR_LAYER 5.9`, `BODY_ADJ_LAYER 22.9`), 44 `*_LAYER` definitions in total in the mobs section. The layer order is needed for composition; in 3D it turns into "which parts to hide" (flags `HIDEJUMPSUIT`, `HIDEHAIR`, `obscured_slots`).
- Body: 6 zones (head, chest, two arms, two legs), the state sprite is `[limb_id]_[zone]_[sex]`; skin color is 16 tones or an arbitrary species color; on top of the body go damage (`dam_mob.dmi`, 162 states), bandages, wounds, "husk".
- Head: hair 222 styles, facial hair 39, gradients 21, lips, eyes (left and right colors separately), colors are arbitrary 24-bit.
- Accessories (`code/datums/sprite_accessories/`): 575 types in total, including clothing accessories 130 (underwear 32, undershirts 56, socks 41), moth wings 27, antennae 24, tails 23, ears 9, horns 6.
- Species: 30 `/datum/species` types; in `config/game_options.txt` 7 are enabled for a round (human, felinid, lizard, moth, plasmaman, ethereal, cerulean). Digitigrade (lizard legs) requires separate clothing sprites (`DIGITIGRADE_UNIFORM_FILE`).
- Clothing by slot: 3,979 types with `slot_flags`: belt 1,283, head 496, jumpsuit 392, outer clothing 379, backpack 361, mask 184, neck 162, ID 137, shoes 103, gloves 92, glasses 85, ears 67. Wearable sprites in `icons/mob/clothing`: 3,551 states (76 files, 4 directions); `greyscale`: 230 JSON configs and 448 item types with a `greyscale_config`.
- Combinatorics (Python, `16 x 222 x 40 x 22 x 2 x 32 x 56 x 41`): a body is about **4.6e11** without colors; one item per slot (+ "empty") gives about **8e27**; colors (24-bit for hair, face, two eyes) add another 10^21 and more.
- Volume of the appearance API in code: `update_appearance` 2,860 calls, `update_overlays` 467 definitions, `update_icon_state` 514, `add_overlay` 351, `mutable_appearance` 889, `emissive_appearance` 268, `vis_contents` 271, `add_filter` 202, `animate()` 956, `particles` 496 mentions, 34 render planes. `grep -rE '<pattern>' --include='*.dm' code | wc -l`.
Confidence: high.

For item 5: according to the Meshy API price list (page `docs.meshy.ai/en/api/pricing`) image-to-3D with a 2K/4K texture costs 30 credits (models meshy-6/7.1; mesh only 20, 8K 35; lightweight models 5-15), remesh 5, UV 5. ⚠️ The figures "100 credits per month on the free plan and 1,000 on Pro" are NOT given on that docs page: they were taken from the page `meshy.ai/pricing` (web plans), which also states that API access is included in Pro; the docs, meanwhile, require buying API credits in advance in the subscription settings, and neither page clarifies whether credits are shared between web and API, so these limits cannot be treated as a ready-made API budget. This gives on the order of 10-20 thousand credits for the slice and 300-500 thousand for parity (about 40 credits per mesh with texture, remesh and UV) before accounting for retries. I did not verify the price of a credit.
For item 4: Kenney Space Kit contains 150 assets under a CC0 license (`kenney.nl/assets/space-kit`); Quaternius Ultimate Space Kit has 92 models, CC0 (`quaternius.com/packs/ultimatespacekit.html`).

Minimum for the Meta vertical slice (my proposal): (L0) a walkable grey-box of about 40 meshes: 19-52 families cover 80% of the objects in the corridors or in three departments; (L1) a playable slice of about 250-350 models; (L2) a visually complete Meta: 274 families at 90% and 2,077 at 100%. In parallel a human character is needed: the body, 2 physiques, about 10 hairstyles, 5 facial hair styles, 20 clothing items, 40 in-hand items, and walking, lying down and striking animations.
Confidence: medium for demand, low for hours and credits.

### F8. Licenses (brief)
`LICENSE` and `README.md`: code is AGPLv3 (GPLv3 until 2014-12-31), "all assets, including icons and sound" are CC BY-SA 3.0 unless otherwise stated; TGS DMAPI is MIT. Per `tgui/README.md` tgui as a whole is covered by the parent AGPL-3.0, while "most of the core" is available under MIT (⚠️ an explicit `@license MIT` header is present in only 51 of the 1,019 `.ts/.tsx/.jsx` files in `tgui/packages` (`08-legal-licensing.md` counts 71 when SPDX is taken into account), so MIT cannot be applied to all of tgui without checking the files). A detailed analysis is in `08-legal-licensing.md`. An external reference point from a neighboring project: SS3D (Unity) licenses its assets as CC BY-NC-SA 4.0, code MIT, pre-alpha status (page `github.com/RE-SS3D/SS3D`; re-checked against the README).
⚠️ **The "unless otherwise stated" caveat is significant in practice.** The attribution files in `sound/` (82 files) name different licenses: CC BY-SA, CC0, CC BY 4.0, but also CC BY-NC 3.0/4.0 ("Attribution NonCommercial") for sounds such as `female_cry1.ogg`, `metal_drop.ogg`, `medkit_open.ogg`, packs of weapon and item sounds, and `sound/music/antag/pirate/attribution.txt` lists CC-BY-NC-SA-3.0. In total there are 28 NC mentions in 11 files. Individual sounds and icons under an NC license are incompatible with a commercial release, even if the project itself accepts copyleft; before using the sound corpus an audit of attributions is needed (analysis in `08-legal-licensing.md`, F9-F10: it also states that most icons and many sounds have no attribution at all). Fonts: only Grand9K Pixel has an explicit license (CC BY 4.0); for Pixellari, Tiny Unicode and VCR OSD Mono, `interface/fonts/license.txt` merely says "website indicates free", and for Spess Font no license is specified.
Confidence: high for the license texts; I did not draw legal conclusions.

## Implications for the 3D port

1. **Do not port the "icon_state + overlays" model.** Introduce into the simulation core an appearance descriptor (model id, set of states, material parameters, attachments) and an "appearance changed" event. 2,860 `update_appearance` calls and 467 `update_overlays` are not code to be rewritten line by line, but places where states need to be emitted. The client (Godot) state selects the mesh, texture, glow and animation.
2. **Build an automatic DMI importer.** It is needed under any strategy: icons for UI and inventory (49 spritesheet classes), placeholders, references for artists. Frequency coverage gives a gradual-replacement scheme: "each of the 11 thousand item types is visible from day one as an extruded placeholder, and the 120 most frequent ones get a hero model".
3. **The choice of asset strategy depends on the camera.** 76% of states have one direction and are drawn in an oblique perspective, so sprites suit a fixed-angle camera or placeholders, but not a free first-person camera. The camera decision must be made before choosing a strategy (see Open questions).
4. **Walls, floor, decals.** 47-state bitmask → a modular wall set (straight, corner, T, cross, end cap) plus materials; about 40 wall materials and 513 floor types are textures/materials on top of one mesh; 151 decal types on Meta (5,731 instances) → projected decals (Godot `Decal`). The 200 source `.png.toml` files are a ready list of templates.
5. **Hidden infrastructure.** Cables (3,631), atmos pipes (about 6.6 thousand) and disposal pipes (1,724) on Meta do not need to be rendered by default: the logic exists, and visibility is turned on by a T-ray/layers mode. This greatly cuts the load on assets and rendering.
6. **Maps.** Convert TGM → a custom chunk format at build time (the parser is trivial, 1.2 s for 632 maps). Needed: multi-floor (IceBox 3 z, Tram/Nebula/Catwalk 2 z), `directional` helpers (3,791 on Meta) → a socket/rotation on a wall, `pixel_x/pixel_y` offsets (about 1,745 on Meta) → sub-tile offsets, areas (171 on Meta, 1,030 in total) as logic and ambience, Meta's 641 light fixtures as a dynamic light budget. Remember that on Meta 75% of the grid is void: store it sparsely.
7. **Procedural generation is rewritten, not converted.** Lavaland/Icemoon are a cellular automaton plus ruin budgets (60/90/16) plus 178 DMM ruins (99+45+34); the automaton and the ruin placement must be ported as code, while the ruins themselves are converted as maps.
8. **Character.** A modular body (6 zones) + attachments (hair 222+39, ears/tails/wings) + clothing as separate meshes fitted to the body (blend shapes or hiding parts by flags such as `HIDEJUMPSUIT`). Pre-rendering combinations is ruled out (4.6e11 bodies, 8e27 outfits). For the slice, 1-2 species (human, possibly lizard) and a limited set of hairstyles are enough; the other 6 enabled species and 23 others are a separate stage. Digitigrade, M/F physiques and height = dimensions of the clothing-fitting matrix.
9. **tgui.** Either a WebView with a `window.Byond` shim (about 20 calls, a "JSON state + act" protocol) keeping the React code, or native Godot UI. ⚠️ A caveat on WebView: Godot core does not have one, so a third-party plugin is needed (for example godot_wry); per its README it supports Windows, macOS and Linux X11 (Android/iOS/web are "planned"), is always drawn on top of the other game elements (it cannot be embedded in a 3D scene), has no transparency on Linux, and uses different engines on different platforms (WebView2, WebKit, WebKitGTK). For the slice, the HUD, lobby, character setup and say are made native; about 25 core windows must be available in any case. A native rewrite of all 352 windows is unrealistic. `ByondUi` (cameras, character preview, mechs) needs 3D viewports.
10. **Sound.** Godot imports `.ogg` directly; the 3,507 files in use are a queue for binding to events, the 1,291 announcer words can be deferred, and the 882 instrument files (MIDI + samples) are not needed for the slice. Positional sounds are already mono.
11. **Effects.** 2,139 `/obj/effect` types, 956 `animate()`, 496 `particles` mentions, 202 filters and 34 planes are material for a rewrite with shaders and VFX, not for conversion. Do not promise effects parity.
12. **What not to do:** convert everything at once (only about 43% of atom types and 32% of item types occur in the maps; the rest is spawned through gameplay); load 1.06 GB of uncompressed frames into memory; treat 4-direction sprites as the basis of the 3D view; expect AI generation or voxelization to solve characters.

## Open questions (for the user to decide)

1. **Camera and visual style**: a fixed angle as in SS13/SS14 (sprites and billboards fit), third person, or first person? A low-poly style, pixel-art voxels, or a hybrid? This determines the entire asset strategy.
2. **Parity scale**: which stations (Meta as the slice, the others as a late target), which species (1, 2 or 7), and are antagonists, chemistry, PDA/NTOS in the first version?
3. **Copyleft**: is the project ready to go under AGPLv3 + CC BY-SA using tg maps, sprites and sounds (and 3D models derived from sprites), or is a clean-room approach with original art needed (in which case strategies 1-2 in the role of a "converter" drop out, leaving 3-5)? ⚠️ Separately: some tg sounds are CC BY-NC; they would have to be excluded or replaced under any commercial plan.
4. **UI**: a WebView wrapper for tgui or native Godot UI? Target platforms (desktop, web export, mobile)? WebView is not available everywhere.
5. **Resources**: are there 3D artists? What is the budget for AI generation (credits) and time? For the slice, 250-350 models and 5 person-months of manual work is a reasonable guideline that is worth confirming.
6. **World units**: how many meters per tile, the wall/ceiling height (sprites do not define height), and whether we make ceilings and multi-floor on Meta.
7. **Depth of customization**: keep 222 hairstyles/39 facial hair styles/16 tones/arbitrary colors, or reduce them?

## Gaps

- I did not measure the real density of opaque sprite pixels (no PIL, and I did not install packages without approval): the voxelization effort estimates do not include the number of voxels and triangles.
- Static type parsing gives a lower bound: `icon_state` values set at runtime are not counted. The classification of tgui windows, "families" and "critical" ones was done by names and by me.
- The hours of manual work, the number of credits for retries and the kitbash coverage shares are assumptions; the price of a Meshy credit and the real reject rate of AI generation were not verified; the quality of voxelization and AI models on tg sprites was not tested.
- The WebSearch limit in the session is exhausted (shared across agents), so external sources are limited to direct pages (Kenney, Quaternius, Meshy, SS3D). The problems of the original game and of earlier porting attempts are not examined here; they are in reports 01-07.
- I did not measure performance (the number of dynamic lights, draw distance, atlas memory).

Method: the numbers for tgstation were recalculated from scratch with separate commands and my own parsers (DMI: a newly written `zTXt` chunk parser; DMM: a newly written TGM parser for MetaStation; DM types: a re-run of `dm_types.py` plus independent greps); external claims were checked by reopening the sources via WebFetch (WebSearch was exhausted in the session). Corrections have been made in the text above.

Not verified: qualitative judgments (whether the kitbash packs are sufficient, the suitability of voxelization and AI generation), the classification of tgui windows by purpose, the heuristic type "families", the price of a Meshy credit, the existence and properties of `Decal` in Godot (common knowledge, but the source was not opened). The remaining F5 map numbers, apart from MetaStation (the number of z-levels was checked for all stations), were not recalculated.

Bottom line: the local numbers are reliable (discrepancies of no more than 1%, and only in the lower bound for types); the main corrections concern sound licensing, the wording about WebView in Godot, and the source of the Meshy limits.
