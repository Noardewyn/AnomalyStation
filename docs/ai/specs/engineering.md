## 2. Rules for a package (the brief every agent reads)

- **Where.** Each package works in its own worktree `.claude/worktrees/eng-eN` on branch `eng/eN`, made by the lead from main with
  `godot/assets/tg` symlinked from the main checkout (the git-ignored sound index the gameplay tests read). Touch only the
  package's own files. Never switch branches, never touch the main checkout, never push.
- **Read first:** `CLAUDE.md`, `docs/ai/translation-rules.md`, `docs/ai/specs/waiting-model.md`; the package's tg DM files and TSX
  windows in `../tgstation/` (read-only). Read narrowly (grep, `sed -n` ranges).
- **Translate tg, do not invent** (D86): the procs the mechanic needs, tg's numbers and order, `// tg: file:line` above each proc,
  as the surrounding files do. The server's `ui_interact`, `ui_data`, `ui_static_data` and `ui_act` are translated from the DM;
  the client window is a translation of tg's TSX in `godot/scripts/Shared/Tgui/Interfaces/` (registered in
  `TguiWindows.cs`), drawn with the existing `UiNode` kinds. A window part the kit cannot draw yet is added to the kit in the
  smallest way, not faked. Templates: commit `90d7e029` (two pump windows, server and client, tests) and `AtmosPump.cs`.
- **The leaves you do not port** stay deferred with `Dm.Deferred(...)` and a row in `docs/ai/specs/not-translated.md` or
  `docs/ai/specs/live-partial.txt`, each with its reason; remove the `live-partial.txt` rows of the procs you translate.
- **Visuals and sounds** (D142): tg's icon states, overlays and sounds of the mechanic run with it; check the client draws them.
- **Regenerate the tracker** after translating (it reads the compiled Core, so never with `--no-build`), with a scratch folder of
  your own so parallel packages do not share one:
  `dotnet run -c Release --project tools/Anomaly.Tools.Types -- --tg /Users/alexey/Desktop/projects/SpaceStation3D/tgstation --opendream /Users/alexey/Desktop/projects/SpaceStation3D/OpenDream --out . --scratch $TMPDIR/anomaly-types-eN`.
  Commit the regenerated files (`docs/ai/specs/generated/`, `src/Core/Tg/Generated/`) in a separate commit after the code commit.
- **Tests:** a Core or client test of the logic (client windows: `tests/Anomaly.Server.Tests/Client/Tgui/`, like
  `AtmosTempWindowsTests`), and a gameplay test on a real server for the mechanic's use (`tests/Anomaly.Server.Tests/Integration/`,
  like `ThermomachineGameplayTests`: open the window, act, see the machine change). Before the commit: `dotnet build
  AnomalyStation.sln` and `dotnet build godot/Anomaly.Client.csproj` with 0 warnings and 0 errors, and the filtered tests of every
  touched area (`dotnet test AnomalyStation.sln --no-build --filter ...`). Not the full suites (the lead runs them at the end).
- **Do not edit** `CHANGELOG.md`, `docs/ai/PORT-CHECKLIST.md`, `docs/ai/DECISIONS.md`, `docs/ai/DEVIATIONS.md`, `docs/ROADMAP.md` or this
  file: put the proposed changelog line, the checklist rows to tick and any deviation (with its reasoning) in the report; the
  lead writes them at the merge. Ask the lead (in the report) for a decision that is the owner's; do not narrow the scope.
- **Commits:** English, in the style of `git log` (what the player gets, the tg files), with NO `Co-Authored-By`, "Generated with"
  or other AI attribution line (D93). Do not start helper agents.
- **Report:** the commits, what runs and what stays deferred (with rows), the tests and their results, the changelog line, the
  checklist rows, deviations, open questions.

## 3. Merging (the lead)

The lead reviews each branch (the diff against the tg source, the tests, the docs rows), rebases it onto main (regenerating the
tracker on a conflict in the generated files: take main's, rebuild, rerun the tool), reruns the builds and the filtered tests,
fast-forwards main, then commits the changelog line, the checklist ticks and any DV row. A release when the owner asks or the
protocol changes (`docs/versioning.md`).
