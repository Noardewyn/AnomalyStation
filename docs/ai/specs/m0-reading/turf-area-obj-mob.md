## 0. Summary (read this first)

1. All nine assigned files were read in full (5281 lines). They are *thin bases*: ~60% of the lines are leaf behaviour (fishing, footprints, slip, rust, acid, VV, examine, verbs) that M0 can stub. The load-bearing parts are small: `turf/Enter` (T:434), `turf/Initialize` (T:139), area contents bookkeeping (A:283-370 + AC), `area/Entered|Exited` (A:581-606), `mob/Initialize|Destroy` (M:26-101), `client/Move` (MM:46-145), `obj/Initialize|Destroy` (O:62-79).
2. Almost everything "engine-ish" these classes lean on is a BYOND builtin the C# shim must own: `loc`/`contents` (raw, hook-free), turf identity = coordinate, `turf.loc == area`, `area.contents += turf` as the area-change primitive, `new X(loc)` placing without Entered, `new turftype(oldturf)` replacing a turf in place, `mob.client`/`key`/`Login`/`Logout`, `step()`, `locate()`, `range()/view()`.
3. The mob is only loosely coupled to `client`: every `client` use in mob.dm is null-guarded (`if(!client) return`, `client?.x`), so a headless mob works. `do_after` touches the client only for the progress bar (datums/timed_actions.dm:37). tg itself ships a stand-in for tests: `/datum/client_interface` (datums/mocking/client.dm) + `mob.mock_client` + `GET_CLIENT` (__HELPERS/mobs.dm:447).
4. Three M0 traps found: (a) `mob.cached_multiplicative_actions_slowdown` is null until `initialize_actionspeed()` runs in `mob/Initialize`; `do_after` does `delay *= null` (timed_actions.dm:50), and DM null is 0, so a mob that skips Initialize makes every do_after instant. (b) every `Move` ends in `Moved` -> `newtonian_move` -> `Process_Spacemove(continuous_move=TRUE)` -> `has_gravity()` (AM:900, 1325, AT:778); an `/area` default `default_gravity = ZERO_GRAVITY` (A:90) spawns a `datum/drift_handler`. The toy area must set `default_gravity = STANDARD_GRAVITY` (as `/area/misc/testroom`, game/area/areas/misc.dm:37-44, does). (c) `turf` identity: tg relies on a BYOND turf reference surviving `ChangeTurf` (T:236-239 comment); C# object refs do not.
5. tg already has the acceptance test for the M0 scenario: `modules/unit_tests/movement_order_sanity.dm` (step into a turf whose `COMSIG_ATOM_ENTERED` handler qdels the mover; expects log order Move, doMove, Moved, Moved). Port it as the M0 Move-chain test. Also `modules/unit_tests/area_contents.dm` (invariants of `turfs_by_zlevel`).

## 3. Lifecycle chains

**Creation (all atoms), AI:65-75, 2-54, 115-159.** `new T(loc, args...)`: engine allocates, applies map preloader vars (`world.preloader_load`, AI:67), places at `loc` *without* Enter/Entered/area hooks, calls `New`. `atom/New` (AI:65) overwrites `args[1]` (the loc slot) with `mapload` and calls `SSatoms.InitAtom(src, FALSE, args)` -> `Initialize(arglist(args))`; the hint result handles LATELOAD (queued only when `mapload`, else immediate), QDEL, and flags BAD_INIT. After: signals COMSIG_ATOM_AFTER_SUCCESSFUL_INITIALIZE, GLOB COMSIG_GLOB_ATOM_AFTER_POST_INIT, and `COMSIG_ATOM_AFTER_SUCCESSFUL_INITIALIZED_ON` sent *to loc* (AI:45-50). `INITIALIZE_IMMEDIATE(X)` (16 uses; __DEFINES/subsystems.dm:96) re-runs InitAtom from `X/New` with mapload=TRUE before SSatoms is up (e.g. `/mob/dead`, modules/mob/dead/dead.dm:3).

## 4. Turf / area / contents maintenance

**Engine contract (BYOND; the shim must reproduce).**
- `atom.loc = X` (raw): removes from `old.contents`, **appends** to `X.contents`; fires NO Enter/Entered/Exited. tg uses raw `loc =` in only ~52 statements (15 bare: AM:680 abstract_move, 739 Move, 1190 doMove; 37 dotted, many on `image`s and the dview mob, __HELPERS/mobs.dm:668-706).
- `turf.contents` = movables with loc==turf, arrival order. `turf.loc` is the `/area` (T:174 `var/area/our_area = loc`; 29 such reads). `turf.x/y/z` are read-only coordinates (T:125 forbids VV edits).
- `area.contents += turf` *moves the turf into that area* (T:261, reader.dm:935, space_reservation.dm:96); `contents -= x` sets `x.loc = null`; the same trick is used on movables (`storage.real_location.contents += target`, mail.dm:565; ~262 raw `contents` mutations, most on containers).
- `area.contents` includes turfs and the movables directly on them; nested contents (items in a bag on a turf) are excluded. Settled: BYOND ref, contents var: "The turfs contained in the area are in the list along with any objs or mobs directly contained by those turfs."; tg comments it as "a filtered loop over world" (A:22-23), so use is avoided: A:236/246/255 (`for(var/turf/T in contents)` mapgen) and A:444 (`for(var/obj/machinery/door/door in src)`).
- `world.turf`, `world.area`, `world.mob` (world.dm:12-14): at world creation the engine fills `maxx*maxy*maxz` with `world.turf` instances in the singleton `world.area` (`GLOB.areas_by_type[world.area]`, game/world.dm:465). `increase_max_x/y` (game/world.dm:456-490) appends new turfs to that area's `turfs_by_zlevel` by hand.

## 8. Hazards and recommended handling

1. **Turf identity (HIGH).** tg depends on turf refs being coordinate-stable across `ChangeTurf` (T:236-239; lists of turfs in areas/SSair/etc. stay valid). A new C# instance breaks every held reference (`area.turfs_by_zlevel`, atmos active lists, `GLOB.starlight`, signal tables). M0: do not implement ChangeTurf (NotTranslated), keep one object per coordinate in a `World.Turfs[x,y,z]` array; decide before M3 (map load builds turfs via `new type(turf)`/ChangeTurf, reader.dm:954-958). Candidate: stable `Turf` object + swappable behaviour payload, or instance replacement with explicit fix-up of `turfs_by_zlevel`/signal tables. Needs an ADR; flag to object-model owner.
2. **Raw `loc` vs hooked move (HIGH).** The shim must expose `Loc` as read-only to translated code and offer one internal `Dm.RawSetLoc(atom, newLoc)` used by `new`, `contents +=/-=`, and the Move/doMove/abstract_move translations; translated `loc = x` statements map to it. Contents order must be arrival order; iteration of `contents` while mutating is common (turf/Initialize T:171-172: `initialize_occupant` may move/delete occupants; comment T:117-118): snapshot-on-enumerate is BYOND's behaviour: settled by the BYOND ref, for list proc: "When you loop through a list, with the exception of looping through world, you're actually looping through a copy of that list." (243 own-contents loops, 181 loops over turf-ish vars).
3. **`turf.loc` is an area (HIGH).** Model as `Turf.Area` (typed) with `Loc` returning it; `area.contents += turf` -> `Area.AddTurfRaw(turf)` (no events). `area.loc == null`; `area.x/y/z` = coordinates of the contained turf with the lowest z, then y, then x (BYOND ref, x var; A:382 warns when z is 0).
4. **`new` placement semantics (HIGH).** `Dm.@new(type, loc, args...)` (wave-0 decision): allocate, assign the id and register, pre-New hook places the atom silently (no Entered; BYOND ref, Entered: "The same goes for creation or deletion of an object at a location."), then `New(loc, args)` through the `Dm.Call` binder, which reaches `Initialize(mapload, rest)` via `atom/New` -> `InitAtom`. tg code passes non-loc args after loc (638 Initialize overrides take extra params; 4306 total). Pick one C# Initialize protocol (e.g. `Initialize(bool mapload, DmArgs rest)`), decided with the atom owner.
5. **Initialize copies (MED).** Turf and space deliberately do not call parent (T:139, space_EXPENSIVE.dm:13); `mob/dead`, `dview`, `oranges_ear` too. Translate each as written; add a unit test for "INITIALIZED_1 set exactly once" per base.
6. **Hint contract (MED).** Initialize must return a hint; wrong/no hint is logged to `BadInitializeCalls` (AI:36-44). Keep `InitAtom`'s checks as asserts; the `UNIT_TESTS`-only `start_tick != world.time` check (AI:19-22) is the "no sleep in Initialize" test to keep.
7. **Mutable null arithmetic (MED).** DM null acts as 0 in math/comparisons (`delay *= cached_multiplicative_actions_slowdown`, `world.time < move_delay` with null `move_delay`). Shim numbers are `float` (D64; BYOND ref, arithmetic operators: "num or null (0)"): a tg numeric var that defaults to null becomes a `float` defaulting to 0 (same arithmetic) unless tg also tests it with `isnull`; test the Initialize order (trap 4a).
8. **Defaults from type chain (MED).** Subtype var overrides map to C# constructor assignments (`name = "floor"` in the derived ctor runs after base ctor, matching DM override semantics); `x = parent_type::x | F` becomes `x |= F`. `initial(v)` needs a per-type prototype value table (V2 converter) or a default instance built without side effects: C# ctors must be pure field init (all side effects live in New/Initialize). Type-level initializers that reference other types' defaults (`/turf/.../kitchen::icon_state`, TO:492) must be evaluated lazily or topologically.
9. **BYOND default `name`.** When no ancestor sets `name`, BYOND derives it from the type: settled by the BYOND ref, name var (atom), default value: "The name of the object type with underscores converted to spaces." (`/obj/item/toy_gun` -> "toy gun"). Toy types should always set it; the converter precomputes it.
10. **Move defined twice / `Moved` re-entrancy (MED).** The second `Move` calls `..()` into the first (AM:763,687); nested `doMove` inside `Entered` handlers resolves the outer pending `Moved` first via `RESOLVE_ACTIVE_MOVEMENT` (AM:1171) -- this is exactly what `movement_order_sanity.dm` checks. Port `active_movement` verbatim (`VAR_PRIVATE/tmp/list`).
11. **Qdel semantics for turfs (LOW).** `QDEL_HINT_IWILLGC` and `QDELETED(mover)` checks sprinkled in `Enter` (T:449-459): `QDELETED` must reflect `Destroy` having started, not GC. Turfs are not queued for GC.
12. **Verbs/`usr` (LOW for M0).** 41 `usr` uses here, almost all inside verbs/VV. M0: translate verb bodies as normal methods; `usr` is the ambient `Dm.usr` (Kernel `World.usr`, captured and restored across sleeps by the sleep awaiter, re-imposed by callbacks), set by the caller (mock client) before a verb runs.
13. **`range()/view()` content (MED).** `range(1, turf)` returns turfs, areas and movables; MM:312 explicitly skips areas. Shim `Range()` must include the area of each turf (or callers' `isarea` check is dead code). `block()` order is x fastest, then y, then z (verify).
14. **Gravity/drift hidden dependency** (trap 4b) and **SSmapping stub fields** touched by these files: `max_plane_offset`, `plane_offset_blacklist`, `z_level_to_plane_offset`, `areas_in_z`, `multiz_levels`, `gravity_by_z_level`.
15. **Mob.Initialize order (LOW).** pre-parent `set_nutrition(rand(...))` consumes RNG before `..()`; RNG call order matters for state-hash determinism (D31).
