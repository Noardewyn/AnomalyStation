## 0. TL;DR (decisions this report supports)
1. Translate `subsystem.dm` + `master.dm` (CheckQueue/RunQueue/enqueue/dequeue/update_nextfire/Loop/Initialize) **literally**; they are pure list/number logic. Make only the *environment* deterministic: virtual `world.tick_usage` (default 0), virtual REALTIMEOFDAY, seeded rand, FIFO sleeper queue. tg already ships this mode: `master.dm:93-98` (seed 29051994 under UNIT_TESTS) and `__HELPERS/stoplag.dm:13-17` (UNIT_TESTS branch = plain `sleep`).
2. Translate `timer.dm` literally (buckets are observable: same-tick timers fire LIFO, wait=0 fires next tick, ids are strings). Do NOT replace by a PriorityQueue.
3. CHECK_TICK (217) = no-op in deterministic mode (TICK_USAGE 0 never exceeds limit 98). `MC_TICK_CHECK` (83) stays real and is translated literally (pause()/resumed protocol): it also tests `src.state != SS_RUNNING`, so it trips after `fire()` slept earlier in the same run even with TICK_USAGE 0 (section 3.8); otherwise it trips only if a test injects virtual usage. `stoplag`(66)/`UNTIL`(48) are real sleeps.
4. The only hard waiting-model requirement in this area: `ignite()` (waitfor=FALSE, returns `SS_SLEEPING` if `fire()` suspends) and `callBack.InvokeAsync()`; plus MC itself as an endless coroutine ordered FIFO among sleepers (do_after relies on it, `datums/timed_actions.dm:103-110`).
5. DM runtime errors end only the innermost proc and return its `.` (`__DEFINES/stack_trace.dm:1` "without ending the current proc"); the port deliberately deviates (wave-0 decision, `docs/ai/DEVIATIONS.md`): C# exceptions unwind to the nearest isolation boundary (sec. 9, hazard 8).

## 1. Time model (everything keys off this)
- `world.fps=20` (`code/world.dm:19`) -> `tick_lag = 10/fps = 0.5` ds; `world.time` in deciseconds, advances 0.5/tick. Type: `float` (D64; DM numbers are float32 too, `SHORT_REAL_LIMIT` maths.dm:13), as the Kernel does (`World.Time => Tick * TickLag`, a float): multiples of 0.5 ds are exact up to 2^23 ds (2^24 ticks, about 9.7 days of game time). Not int ticks in translated code (formulas multiply by tick_lag); the Kernel keeps the tick counter as int64 (D31).
- `BUCKET_LEN = world.fps*60 = 1200` (timer.dm:2). `TICK_LIMIT_RUNNING = max(100-2-world.map_cpu,70) = 98` (`__DEFINES/_tick.dm`), `TICK_LIMIT_MC=70`, `TICK_LIMIT_TO_RUN=70`.
- Unit macros are *postfix token macros without parens* (`__DEFINES/time.dm:65-82`): `N SECONDS`=`N *10`, `MINUTES`=`SECONDS*60`, `TICKS`=`*world.tick_lag`. So `x / 1 MINUTES` == `x/1*10*60` (real tg quirk: `controllers/subsystem/ipintel.dm:71`, `modules/mob/living/carbon/human/_species.dm:1339`). Expand at the preprocessor level, never "semantically".
- `DS2TICKS(d)=(d)/tick_lag`, `TICKS2DS(t)=t*tick_lag`. DM `round(x)` == floor (`__DEFINES/maths.dm:44` comment; `CEILING(x,y)=-round(-x/y)*y`, `ROUND_UP(x)=-round(-x)` depend on it); `round(x,y)` = nearest multiple. C# `Math.Round` (banker's) is WRONG for both.
- `REALTIMEOFDAY` (maths.dm:26, 64 uses) = `world.timeofday + MIDNIGHT_ROLLOVER*checks`; used by TIMER_CLIENT_TIME timers (35 uses), tick drift, init timing. Deterministic mode: `timeofday = floor(world.time)` (virtual).

## 2. Subsystem definition mechanics
Base vars (subsystem.dm:10-123): `name, wait(=20), priority(=50), ss_flags, init_stage(=MAIN=3), runlevels(=SETUP|GAME|POSTGAME=14), can_fire, dependencies/dependents, init_order(derived)`, runtime: `last_fire,next_fire,cost,tick_usage,tick_overrun,state,slept_count,paused_ticks,paused_tick_usage,ticks,times_fired,postponed_fires,queued_time,queued_priority,queue_next/prev`.
- Flags (MC.dm:44-75): NO_INIT 1, NO_FIRE 2, BACKGROUND 4, TICKER 8, KEEP_TIMING 16, POST_FIRE_TIMING 32, OK_TO_FAIL_INIT 64. States (MC.dm:78-83): IDLE0 QUEUED1 RUNNING2 PAUSED3 SLEEPING4 PAUSING5. Stages: FIRST1 EARLY2 MAIN3 LAST4=MAX.
- Declaration macros (MC.dm:92-145): `SUBSYSTEM_DEF(X)` = `GLOBAL_REAL(SSX)` + `New(){NEW_SS_GLOBAL(SSX); PreInit();}`. Variants (PROCESSING_/TIMER_/MOVEMENT_/FLUID_/VERB_MANAGER_/AI_CONTROLLER_) also emit `fire(){..()}` ("just for profiler") -> skip in C#. 140 `*SUBSYSTEM_DEF` in tree.
- **Subtype `ss_flags = X` REPLACES (not ORs) the parent value**: `SSobj`/`SSdcs` set `SS_NO_INIT` only, so they are NOT background/post-fire (processing.dm:6 vs obj.dm:4, dcs.dm:3); `SSfastprocess` sets none and inherits BG|POST_FIRE|NO_INIT. C#: plain assignment in derived ctor/field initializer; do not `|=`.
- Init order is not a static define any more: `init_order` assigned at boot (master.dm:432-441) from stage -> topological sort over `dependencies`/`dependents` (master.dm:337-429; stack pop from END of `unsorted_subsystems`, so reverse insertion order) -> `subsystems` was first sorted by `cmp_subsystem_init_stage` (stable) and `subtypesof` order.
- `subsystems` is re-sorted by NAME (`cmp_subsystem_display`, master.dm:433; `sorttext(b.name,a.name)`, case-insensitive ascending) BEFORE the first Loop -> **name order is the tie-break for equal priority** (sec. 3).

## 3. MC algorithm -> deterministic executor spec
### 3.1 Boot (master.dm:323-477, 485-552, 564-585)
`Initialize(delay,init_sss,tgs)` [waitfor=0]: `sleep(delay)`; build `stage_sorted_subsystems`; resolve `dependents`->`dependencies` (type paths -> instances); topo sort; per stage per SS: `init_order=++n; init_subsystem(ss); CHECK_TICK`; after stage 1 completes: `SetRunLevel(1)` (=LOBBY idx 1) + `StartProcessing(0)` once. `init_subsystem`: NO_INIT or already initialized -> `initialized=TRUE`, skip; else `Initialize()` result in {FAILURE -2, NONE -1, SUCCESS 2, NO_NEED 3, NO_MESSAGE 4}; FAILURE -> `initialized=FALSE, can_fire=FALSE`; else send `COMSIG_SUBSYSTEM_POST_INITIALIZE`. End: `world.change_fps(config fps)`, **`sleep(1 TICKS)`**.
`StartProcessing` [waitfor=0] `do { started_stage=init_stage_completed; rtn=Loop(started_stage) } while(rtn==NEWSTAGES && ...)`; on abnormal exit `Recreate_MC()` (skip in port: fail loudly).
`SetRunLevel(flag)`: `current_runlevel = log(2,flag)+1` (index 1..4, NOT a mask). Use `BitOperations.Log2((uint)flag)+1`; `Math.Log` can return 2.9999999.
Headless trace: with CHECK_TICK a no-op, Initialize runs synchronously after the first `StartProcessing(0)` (which runs MC iteration 1 inline until its first `sleep`), `init_stage_completed` jumps to 4; at next tick MC returns `NEWSTAGES` and `Loop(4)` restarts with everything.

### 3.2 Loop prelude (master.dm:588-657) - per `Loop(init_stage)`
- Skip `SS_NO_FIRE` and `SS.init_stage > init_stage`. Reset `queued_time/queue_*`, `state=IDLE`.
- **Non-BG tickers** `(flags&(TICKER|BACKGROUND))==TICKER`: collected in `tickersubsystems`, `timer += TICKS2DS(rand(0,1)); SS.next_fire=timer` (cumulative 0/0.5ds stagger), and they **ignore `runlevels`**: `I += tickersubsystems` appends them to EVERY runlevel list (master.dm:638-641). (So SStimed_actions runs in LOBBY too.)
- Others: if `SS.init_stage == init_stage-1 && (SS.runlevels & current_runlevel)` (idx-vs-mask quirk, keep) -> `next_fire = world.time + TICKS2DS(rand(0, DS2TICKS(min(delay,2 SECONDS))))`; stage==init_stage SS keep `next_fire=0` (fire at once). Added to `runlevel_sorted_subsystems[bit]` for each set runlevel bit (GLOB.bitflags = 1..32768); warn if none.
- Sort every runlevel list and tickers by `cmp_subsystem_priority` ascending (stable). `runlevel_sorted_subsystems[cached_runlevel]` out of range = DM runtime: toy world must register >=1 SS spanning the runlevels it sets (or C# list auto-grow).

### 3.3 Iteration (master.dm:659-793), headless reduction
Per MC wake (every tick when `processing=1`): drift math (virtual -> 0); `if init_stage!=init_stage_completed return NEWSTAGES`; `processing<=0` -> `sleep(1 SECONDS)`; anti-contention heuristics are inert at usage 0 (`sleep_delta` stays 1; MC_AVERAGE_FAST decays to 1) - translate verbatim, cheap; Failsafe spawn (:701) -> remove (or keep `Failsafe` stub non-null); `skip_ticks` (set by `laggy_byond_map_update_incoming`) restricts to tickers; runlevel change -> reschedule new SS (:707-722); `CheckQueue`; `RunQueue` if queue_head; error_level/SoftReset only on `<=0` returns; `iteration++; last_run=world.time`; `current_ticklimit = TICK_LIMIT_RUNNING (*2 while init_stage != MAX)`; `sleep(tick_lag*(processing*sleep_delta))`.
`sleep()` arg may be fractional (sleep_delta float): a positive delay becomes `max(1, floor(ds / tick_lag))` ticks (wave-0 tick decision; OpenDream `ProcScheduler.Delays.cs` CreateDelay: "Gets rounded down to a number of ticks" and "Anything above 0 deciseconds should be at least 1 tick"), 0 or negative resumes in the same tick after everything already queued.

### 3.4 CheckQueue (:796-826)
For each SS in `subsystems_to_check`: skip if `state!=IDLE`, `can_fire<=0`, `next_fire>world.time`; `SS_NO_FIRE` -> remove from list; KEEP_TIMING non-ticker catch-up guard `last_fire + wait*0.75 > world.time` -> skip; `postponed_fires>=1` -> `--`, `update_nextfire()`, skip; else `enqueue()`.

### 3.5 enqueue / dequeue (subsystem.dm:203-272) - priority linked list
Insert before the first node that: node is BG and new is not; or (same class and node.queued_priority < new.priority); non-BG node vs new BG -> skip; non-BG node vs new TICKER -> break (insert before). Updates `queue_priority_count[_bg]`, sets `state=QUEUED`, `queued_time=world.time`, `queued_priority`.
**Dead branch (subsystem.dm:214)**: `queue_node_flags & (SS_TICKER|SS_BACKGROUND) == SS_TICKER` parses as `flags & ((12)==8)` = `flags & 0` (DM `==` binds tighter than `&`, same as C/C#). The author clearly meant the parenthesised form used at :215/:607. Settled: the BYOND ref operator table lists `== != <> ~= ~!` on the line above `&` ("Each line has higher order of operations than the next"); OpenDream's parser takes `ExpressionComparison` as the operands of `&` (DMParser.cs:1994-2000, `ExpressionBinaryAnd`). Net effect: every node takes the `else if`/`else` branches, so a new non-BG ticker always inserts at HEAD. Port literally (the comparison is 0, so the test is `flags & 0`; write the bool-to-int conversion explicitly with a `// tg quirk` comment) so golden orders match; C# will not compile `int & bool`, forcing a conscious choice. Other DM-vs-C# precedence differences from the same table: DM puts `< <= > >=` ABOVE `<< >>` (C# is the reverse), and `in` binds loosest of all.
**Resulting fire order within one tick (when everything is enqueued in one CheckQueue)**: (1) non-BG tickers: priority DESC, ties in REVERSE name order; (2) non-BG non-tickers: priority DESC, ties name ASC; (3) BG: priority DESC, ties name ASC. Paused/sleeping SS re-`enqueue()` by the same rule.

### 3.6 RunQueue (:831-957)
`while(ran && queue_head && TICK_USAGE < TICK_LIMIT_MC)`: walk list; budget = `queue_priority_count` (or `_bg` once a BG node seen; non-BG after BG = error path, log, `.=-1`); `tick_remaining = TICK_LIMIT_RUNNING - TICK_USAGE`; `pct = remaining*(prio/budget)`; `pct = max(pct*0.5, pct - tick_overrun)`; `Master.current_ticklimit = round(TICK_USAGE+pct)` (floor); `state=RUNNING; last_type_processed=node; r = node.ignite(was_paused)`; `if r==RUNNING r=IDLE`; `budget -= prio`; `tick_overrun = max(0, MC_AVG_FAST_UP_SLOW_DOWN(tick_overrun, usage-pct))`; `node.state=r`; if `r==PAUSED` -> `paused_ticks++`, keep queued, go next; else update `ticks,tick_usage,cost`, `queue_priority_count -= prio`, `last_fire=world.time; times_fired++; update_nextfire(); queued_time=0; dequeue()`. A SS that returned `SLEEPING` is dequeued but stays `state=SLEEPING` (skipped by CheckQueue) until its `fire()` finishes (ignite tail sets IDLE, `slept_count++`).
`skip_ticks` -> only tickers run. Inner `if (ran && TICK_USAGE > TICK_LIMIT_RUNNING) break`.

### 3.7 update_nextfire (subsystem.dm:179-198) - exact formulas (tick_overrun=0 headless)
- TICKER: `next_fire = world.time + tick_lag*wait` (wait counts ticks).
- POST_FIRE_TIMING: `world.time + wait + tick_lag*(overrun/100)`.
- KEEP_TIMING: `next_fire += wait` (may fire several times to catch up, at most 25% faster via CheckQueue guard).
- default: `queued_time + wait + tick_lag*(overrun/100)`.
- `reset_time=TRUE`: `world.time + (ticker? tick_lag*wait : wait)`, `postponed_fires=0`.
Cadence in ticks: processing 20, fastprocess 4, obj 40, mobs 40, dcs 20, timer/timed_actions 1.

### 3.8 pause()/MC_TICK_CHECK protocol
`MC_TICK_CHECK = (TICK_USAGE > Master.current_ticklimit || src.state != SS_RUNNING) ? pause() : 0` (MC.dm:1). `pause()`: RUNNING->PAUSED, SLEEPING->PAUSING, returns 1. The SLEEPING case is reachable with TICK_USAGE 0: RunQueue sets `state = SS_RUNNING` (master.dm:896); `ignite` (waitfor=FALSE) does `. = SS_SLEEPING` before `fire()` (subsystem.dm:147-148), so a `fire()` that sleeps hands SS_SLEEPING back and RunQueue stores it (master.dm:902, 922); when `fire()` resumes, its next `MC_TICK_CHECK` sees `state != SS_RUNNING`, `pause()` turns SLEEPING into PAUSING and `fire()` returns, and ignite's tail re-enqueues the SS as PAUSED (subsystem.dm:153-158). tg logs such subsystems (`slept_count`, master.dm:141-142). fire() must `if(MC_TICK_CHECK) return;` and be re-enterable via `resumed` + a `currentrun` list (48 `resumed` uses, 178 `currentrun`). `ignite(resumed)` (subsystem.dm:139-158): `. = SS_SLEEPING` while `fire()` runs; after sync return `. = state`; `SLEEPING` -> `slept_count++; state=IDLE`; `PAUSING` -> `enqueue()` again keeping `queued_time`, `state=PAUSED`. `MC_SPLIT_TICK_INIT/MC_SPLIT_TICK` (6 uses) manipulate `Master.current_ticklimit`.

## 6. Timer subsystem (timer.dm) - API and semantics
### API (macro `addtimer(args...)` = `_addtimer(args, file=__FILE__, line=__LINE__)`, subsystems.dm:218)
`_addtimer(callback, wait=0, flags=0, timer_subsystem=SStimer, file, line)` -> returns: `timer.id` (string `"1","2",..` when TIMER_STOPPABLE, else `TIMER_ID_NULL=-1`); on UNIQUE hit: existing id if that timer is STOPPABLE else null. `deltimer(id|timedevent, ss)` -> bool (id `-1` CRASHes; spent timers deletable only with TIMER_DELETE_ME). `timeleft(id,ss)` -> ds or null. `updatetimedelay(id,new_wait,ss)` only for LOOP. Uses: addtimer 1611 (1216 `CALLBACK(src,`, 91 `GLOBAL_PROC`), deltimer 191, timeleft 36, updatetimedelay 3.
Flags (subsystems.dm:33-61): UNIQUE 1<<0 (189 uses), OVERRIDE 1<<1 (108), CLIENT_TIME 1<<2 (35), STOPPABLE 1<<3 (193), NO_HASH_WAIT 1<<4 (14), LOOP 1<<5 (10), DELETE_ME 1<<6 (127).
### Rules
- `wait`: `ceil to tick_lag, min tick_lag` (`wait=0` => NEXT tick, never same tick); CLIENT_TIME: `max(ceil(wait),1)`; `>=INFINITY(1e31)` CRASH; negative -> stack_trace then clamped.
- UNIQUE hash = `Join("|||||||", [object, "(REF)", delegate, flags&CLIENT_TIME, (wait unless NO_HASH_WAIT), ...arguments])`; hit: spent -> pretend absent; OVERRIDE -> qdel old; else return existing id. OVERRIDE w/o UNIQUE = stack_trace.
- `new /datum/timedevent`: id via `num2text(nextid,100)`, `nextid++` (jumps past 2^24 via `min(1,2**round(nextid/SHORT_REAL_LIMIT))`; irrelevant in C#, use `long`); registers in `hashes`/`timer_id_dict`; `LAZYADD(callback.object._active_timers, src)` (datum.dm:25,133 -> Destroy qdels live timers); CRASH if `timeToRun < world.time || < head_offset` (non-client).
- Buckets: `BUCKET_POS = ((ROUND_UP((ttr-head_offset)/tick_lag)+1) % BUCKET_LEN) || BUCKET_LEN` (1-BASED, 1..1200, index p <-> time `head_offset+(p-1)*tick_lag`). `TIMER_MAX = head_offset + TICKS2DS(BUCKET_LEN+practical_offset-1)`; later timers go to sorted `second_queue` (BINARY_INSERT, ties after equals) and migrate when a bucket drains (:187-214).
- **bucketJoin inserts at bucket HEAD** (:585-589) and fire pops from head (:158) => timers due the same tick run in REVERSE creation order. This holds for migrated timers too: `second_queue` keeps equal-TTR timers in creation order (BINARY_INSERT puts ties after equals, `__HELPERS/_lists.dm:155` `<=` goes right) and migration (:191-214) `bucketJoin`s them in that order with head insertion, so equal-TTR timers always fire last-created-first, whether inserted directly or migrated from second_queue. Port literally; golden test (b) covers both paths.
- `fire()` (:85-216): client timers (REALTIMEOFDAY, own list); wrap `practical_offset>BUCKET_LEN` (`head_offset += TICKS2DS(BUCKET_LEN)`); `reset_buckets()` if `length!=BUCKET_LEN || world.tick_lag != bucket_resolution` (also invoked by `world.on_tickrate_change`, world.dm:517); `while(practical_offset<=BUCKET_LEN && head_offset+(po-1)*tick_lag <= world.time)` drain buckets: `bucketEject(); if !spent {spent=world.time; callBack.InvokeAsync(); last_invoke_tick=world.time}`; LOOP -> re-time `world.time+wait` + `bucketJoin` (skip if QDELETED); else `qdel`; `if MC_TICK_CHECK break`.
- `TIMER_LOOP` timers re-arm from *fire time* (`world.time + wait`), not from previous TTR.
- Timer subclasses with own buckets: `runechat`, `sound_loops` (TIMER_SUBSYSTEM_DEF) -> not M0.
- `QDEL_IN(item,t)` = `addtimer(CALLBACK(GLOBAL_PROC, GLOBAL_PROC_REF(qdel), t>GC_FILTER_QUEUE? WEAKREF(item):item), t)` (__DEFINES/qdel.dm:59): needs weakref + qdel shim.
- `datum/callback` (datums/callback.dm): `object` (GLOBAL_PROC sentinel string if falsy), `delegate` (proc name/path), `arguments`, `user` weakref of `usr`; `Invoke`/`InvokeAsync` (waitfor=FALSE) = `call(object,delegate)(arglist(arguments+args))`; `Invoke` returns early if `!object`; `GLOBAL_PROC` uses `call(delegate)(...)`. `qdel(callback)` is refused (stack_trace). Helper macros `VARSET_CALLBACK` (56 uses, `___callbackvarset` writes var by NAME), `TRAIT_CALLBACK_*`.
- qdel on timedevent: `Destroy` returns `QDEL_HINT_IWILLGC` -> `gc_destroyed = world.time` (garbage.dm:390). `QDELETED(x)=isnull(x)||x.gc_destroyed` (nonzero/non-null). ## 7. Waiting-model requirements arising here (see docs/ai/specs/waiting-model.md)
1. `sleep(ds)`: a positive delay wakes after `max(1, floor(ds / tick_lag))` ticks; resumed procs run in order (wake_tick, sleep-call sequence) (comment master.dm:677-678; timed_actions.dm:110 "await will tick first before the subsystem itself"). MC `Loop` and `timed_action.await` are both 1-tick sleepers => relative order is fixed by who called `sleep` first in the previous tick. `sleep(0)` (and negative) resumes in the same tick after everything already queued (OpenDream `ProcScheduler.Delays.cs` CreateDelayTicks: "When the delay is <= zero, we should run again in the current tick"). Port tick order (wave-0 decision): `World.Step` = Tick++, reseed RNG, `Scheduler.RunDue` (woken sleepers FIFO by (tick, seq); the MC `Loop` is a scheduler coroutine started at world start, so subsystems fire inside this drain), then the registered phases (player commands, later replication), each followed by another `RunDue` for zero-delay work. A do_after started by a player-command phase therefore sleeps after the MC did in that tick, and from then on the MC wakes first each tick (the opposite of tg's comment at timed_actions.dm:110; see timed-actions-helpers.md section 1 for why the poll count and the result tick are the same).
2. waitfor=FALSE call: callee runs synchronously until first suspension; caller continues; `.` (default return) at that moment is the call's value (`ignite` returns `SS_SLEEPING`). waitfor=FALSE is a property of the callee slot and is inherited by overrides (hazard 9). C# shape (wave-0 decision, waiting-model.md): a callee-side wrapper, so callers call `ignite()` like a normal proc and receive `.` at the callee's first suspension (a DotBox-style holder for `.`); the continuation is re-queued by the scheduler.
3. `INVOKE_ASYNC` (942) and `ASYNC`=`spawn(-1)` (23): the call site detaches the callee, `Waiting.Detach(Foo(...))` (a bare `_ = Foo();` is forbidden). `spawn()`/`spawn(d)` (12) schedule their body through `Dm.spawn(d, async () => ...)`. `set waitfor=FALSE` (125 procs) is the callee-side form of item 2.
4. Endless coroutines: `Master.Loop`, (Failsafe.Loop). Every tick the world drains the scheduler (`Scheduler.RunDue`).
5. Exceptions: see sec. 9.

## 9. Hazards
1. **enqueue precedence bug** (3.5), settled from the BYOND operator table. Port literally.
2. **Tickers ignore runlevels; non-BG ticker detection differs between Loop (parenthesised) and enqueue (not).**
3. **Name-order tie-break** relies on `sortTim` being STABLE (timsort) and `sorttext` case-insensitive; C# `List.Sort` is unstable -> translate tg's `sortTim` (stable) instead of calling `List.Sort`. `sorttext(a,b)>0` iff a<b in BYOND (so `cmp_text_asc(a,b)=sorttext(b,a)`).
4. **`ss_flags`/`wait` override semantics** (sec. 2); mixed units: TICKER `wait` is ticks, others ds (TICKER|BG tickers like ai_movement go through the normal runlevel path with ticks-wait).
5. **`for (i in 1 to N)` loop-variable value after normal exit / empty range / break** is relied on to compute `Cut(1, i+1)` (timer.dm:107-139, 191-214, 290-330). Settled by OpenDream (the BYOND ref only says the end is inclusive): `CreateRangeEnumerator` pops start, end and step once (DMOpcodeHandlers.cs:208-221), and `DreamValueRangeEnumerator.Enumerate` does `_current += step; ... if (successful) { // Only assign if it was successful` (DreamEnumerators.cs:21-34). So after a normal exit `i` holds the last in-range value N, on an empty range `i` keeps its previous value (timer.dm:191 sets `var/i = 0` first, so `if (i)` skips the Cut), and after `break` it holds the current value. A C# `for (i = 1; i <= N; i++)` leaves N+1 instead: translate with bounds evaluated once and `i` assigned only in range (or with the explicit processed counter that translation-rules.md section 6 asks for, which gives the same result), and pin it with a unit test.
6. **Bucket order LIFO** and **1-based list math** (BUCKET_POS, `bucket_list[p]`): wrap in 1-based `DmList` or offset carefully; `%` with `|| BUCKET_LEN`.
7. **Floating arithmetic**: all wait/time values are multiples of 0.5 -> exact in float32 up to 2^23 ds, about 9.7 days (D64); `MC_AVERAGE*` use 0.7/0.3 etc. (non-exact, fine). If tick_lag changes, `reset_buckets` runs.
8. **Runtime isolation**: DM runtime ends only the innermost proc and returns its `.`; the port deviates (wave-0 decision, `docs/ai/DEVIATIONS.md`, never described as DM semantics): C# exceptions unwind through their callers to the nearest isolation boundary, where `World.ReportRuntime` logs them and execution continues. Boundaries: each scheduler entry, `Waiting.Detach`, subsystem `fire`/`ignite` (RunQueue maps leftover `RUNNING` to `IDLE`), each timer callback, each signal handler call inside `_SendSignal`, each callback `Invoke`, per-item `thing.process()` in processing subsystems and `Life()` in SSmobs, `InitAtom` during atom initialization. tg code that inspects `.` after a runtime gets an explicit try/catch where it is translated: `CheckQueue` (master.dm:797 `. = 0 //so the mc knows if we runtimed`) and `RunQueue` (:832 `. = 0`, "Returns 0 if runtimed"), whose `<= 0` results drive Loop's error handling (:728, :744), and `Recreate_MC` (:257 `. = -1 //so if we runtime, things know we failed`). `stack_trace()` must be log-and-continue (never throw); `CRASH()` throws `DmCrashException`; fail-fast in test builds.
9. **`process()` waitfor inheritance**: parent has `set waitfor=FALSE` (processing.dm:48-49) and every override inherits it. Settled by OpenDream `DMCompiler/DM/DMCodeTree.Procs.cs:36-41`: "if (procDef.IsOverride) { ... if (parent.Attributes.HasFlag(ProcAttributes.DisableWaitfor)) proc.Attributes |= ProcAttributes.DisableWaitfor;" (tg has no `set waitfor = TRUE` to undo it). So a sleeping `process()` does NOT stall `fire()`: the call returns the override's `.` at its first sleep (usually null, so not PROCESS_KILL) and `fire()` goes on. The same holds for the 71 LateInitialize, 44 Bumped and 92 ex_act overrides, `Life`, `area/Entered`. Translation: the slot carries the callee-side waitfor=FALSE wrapper (waiting-model.md), and a kernel test checks that a sleeping `process()` override does not suspend `SSprocessing.fire`.
10. `Master.current_ticklimit`, `init_stage_completed`, `random_seed` are `static` (class-level) in DM: in the port they live in the per-World container reached through `World.Current` (wave-0 decision; never C# static mutable fields, so parallel tests can run separate Worlds). Local `var/sleep_delta`/`var/state` shadow fields (master.dm:651,902) -> use `this.`.
11. `GLOB.bitflags` indexing and `runlevel_sorted_subsystems[cached_runlevel]` may be out of range in a toy world (DM runtime / C# exception).
12. Non-determinism sources to pin: rand, `subtypesof` order, `global.vars` order, REALTIMEOFDAY, Stopwatch (rustg_time), TICK_USAGE, `world.cpu`, dictionary iteration order (use insertion-ordered maps; BYOND assoc lists keep insertion order).
13. Timer string forms (`"Timer: ..."` debug, `timer_info` list built per timer, `getcallingtype`) are pure perf/debug overhead; drop but keep `source` as translator-provided `"dm/file.dm:line"`.
14. SS_NO_FIRE subsystems are removed from `subsystems_to_check` lazily (CheckQueue mutates the list while iterating `for(thing in list)` + `-= thing`): iterate a copy/index carefully.
15. `Master.Initialize` uses `CHECK_TICK` between inits: with no-op CHECK_TICK, boot is one synchronous burst (differs from real tg phases, intended).
